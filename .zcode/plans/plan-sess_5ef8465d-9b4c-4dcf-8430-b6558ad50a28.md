# 实训室多柜指纹锁系统改造方案

## 用户确认的关键决策
1. **数据架构**：保持现状（SD 卡为权威数据源，上位机每次读写 SD）— 不重构为 PC 主存储
2. **锁数量**：固定 `LOCK_COUNT=4`
3. **副指纹槽位**：AS608 ID 随机分配，柜子 NVS 自管理 "AS608槽位 ↔ 用户 ↔ 权限" 映射；主/副都共用同一个 ID 空间，靠 NVS 记录的 `is_backup` 标记区分
4. **实施范围**：一次性全改（固件 + WPF + 协议 + 文档）

## 当前系统 vs 需求文档的差异（要解决的 GAP）

| # | 差异 | 现状 | 目标 |
|---|------|------|------|
| G1 | **10秒开锁窗口流程反转** | 按键→验证指纹→直接开锁3秒 | 验证指纹→10秒窗口→按键开锁 |
| G2 | **指纹状态 LED 指示** | 无（只有 Mesh 状态 LED） | 识别中闪烁/成功绿灯/失败红灯闪烁 |
| G3 | **取消键在验证窗口生效** | 取消只中止录入 | 取消中止指纹验证窗口 |
| G4 | **设备专属副指纹** | 不存在；每用户 1 模板；`writeTemplate` 是桩函数 | 本机可录入副指纹，弹窗选覆盖主/仅本机备用 |
| G5 | **教师数据范围隔离** | 仅 UI 隐藏菜单，服务层未按 ClassId 过滤 | Service 层强制按 ClassId 过滤 |
| G6 | **批量操作 UI** | 仅"重新同步全部权限" | 增柜子批量权限/批量清除指纹/批量分配学生 |
| G7 | **状态可视化增强** | 已有 Dashboard + Device 列表 | 补充学生绑定设备明细、各锁权限明细 |

## 第一部分：ESP32 柜机固件改造

### 1.1 `config.h` — 新增 LED 引脚与窗口时长
- 新增 `FP_LED_IDENTIFY_MS`、`FP_LED_SUCCESS_MS`、`FP_LED_FAIL_MS` 闪烁参数
- 新增指纹状态 LED：`FP_STATUS_LED_PIN`（如 GPIO2 复用受限制则用 74HC595 的保留位或新增独立 GPIO）。**决策**：由于硬件未定型，采用**软件抽象**：在 `config.h` 用 `#define FP_STATUS_LED_USE_595` 切换"复用 595 第 8 位/独立 GPIO"两种实现；默认 `#define FP_STATUS_LED_PIN 41`（备用 GPIO，若硬件用 595 则在 lock_control.cpp 统一驱动）
- 新增 `VERIFY_WINDOW_MS 10000`（验证后 10 秒操作窗口）
- 新增 `WAIT_FINGER_TIMEOUT_MS` 保持 30s（首次等待手指按压，与窗口分离）

### 1.2 `message_handler.h` — 状态机重构
将现有三态 `STATE_IDLE / STATE_WAIT_FINGER / STATE_ENROLLING` 扩展为：
```
STATE_IDLE
STATE_WAIT_FINGER        // 持续轮询指纹（按键不再前置，常态可识别）
STATE_VERIFIED_WINDOW    // 验证成功后的 10 秒操作窗口
STATE_ENROLLING          // 录入（含主/副）
```
- `STATE_WAIT_FINGER` 不再由按键触发，而是 **IDLE 时常态轮询指纹**（Fingerprint::verifyFingerprint 每次循环调用）
- 验证成功 → 记录 `verifiedUserId/verifiedFpId/verifiedPerms` → 进入 `STATE_VERIFIED_WINDOW`，启动 10s 定时器，点亮绿灯
- 在 `STATE_VERIFIED_WINDOW` 中：收到按键 → 若该锁在 `verifiedPerms` 内 → `LockControl::openLock(lockId)` 并回到 IDLE；超时 → 清空权限回 IDLE 灯灭；取消键 → 回 IDLE 灯灭
- 删除 `pendingLockId` 在 `STATE_WAIT_FINGER` 时的语义；保留给录入流用

### 1.3 `message_handler.cpp` — 主流程改造
- `init()`：开机进入 `STATE_WAIT_FINGER`（常态轮询）
- `onKeyPressed(lockId)`：
  - 若 `STATE_VERIFIED_WINDOW` 且 `lockId` 在已验证权限内 → 开锁，回 IDLE
  - 若 `STATE_VERIFIED_WINDOW` 但无该锁权限 → 日志记 `no_permission_in_window`，灯闪红一下不回 IDLE（窗口未结束）
  - 若 `STATE_ENROLLING` → 忽略
- `onCancel()`：扩展为可在 `STATE_VERIFIED_WINDOW` 中止（原录入中止逻辑保留）
- `update()`：
  - `STATE_WAIT_FINGER`：调用 `Fingerprint::verifyFingerprint()`，匹配成功则载入权限进窗口态，点亮绿灯常亮
  - `STATE_VERIFIED_WINDOW`：检测超时（10s）回 IDLE 并灭灯；指纹再次按压可在窗口内刷新（可选，初版不实现）
  - `tryLocalPermission` 拆为两步：`loadVerifiedPermission(fpId)` 仅加载不立即开锁；`openIfPermitted(lockId)` 在窗口态按键时调用
- 验证失败时（指纹未匹配）：红灯闪烁 3 次（约 1.5 秒）后回 `STATE_WAIT_FINGER`

### 1.4 指纹状态 LED 驱动 — 新增 `led_indicator.h/.cpp`
新建轻量模块封装指纹状态指示：
```cpp
class FpLed {
public:
    static void init();
    static void setIdentifying();   // 识别中：慢闪（500ms周期）
    static void setSuccess();        // 成功：绿灯常亮（持续至窗口结束）
    static void setFail();           // 失败：红灯闪烁3次
    static void setOff();            // 灭
    static void update();            // 主循环驱动闪烁
};
```
- 内部状态机 + 时间戳，避免阻塞主循环
- 默认实现：单 GPIO 三色无法表达，因此采用**双色 LED 抽象**：`FP_LED_GREEN_PIN` + `FP_LED_RED_PIN` 两个独立 GPIO（默认 GPIO41/GPIO38 或预留扩展位）；若硬件为单色 RGB，提供 `setRgb(r,g,b)` 适配
- 在 `config.h` 新增引脚定义并在 IO 分配文档登记

### 1.5 副指纹（设备专属备用指纹）— Storage 扩展
**核心策略**：AS608 ID 与全局 fingerprint_id 解耦，柜子 NVS 自维护映射表。

在 `config_common.h` 的 `UserPermission` 结构体中新增字段：
```cpp
struct UserPermission {
    int fingerprint_id;       // 全局逻辑ID（来自上位机下发，主指纹用）
    int local_fp_id;          // AS608 物理槽位（柜子本地分配，主/副共用）
    bool is_backup;           // false=主指纹（全局下发），true=本机副指纹
    uint32_t user_id_num;
    String user_id;
    String name;
    UserRole role;
    bool lock_perm[LOCK_COUNT];
    uint32_t expire_days;
    bool valid;
};
```
- **记录格式变更**：`PERM_RECORD_SIZE` 从 12 字节升到 16 字节（加 `local_fp_id(2B)` + `is_backup(1B)` + 保留 1B）。版本号 +1 触发兼容性处理：旧的 12B 记录读取时 `local_fp_id = fingerprint_id`、`is_backup=false`
- `storage.cpp` 新增本地副指纹表管理：
  - `Storage::addBackupFingerprint(userId, as608Id, perms)` — 写入 NVS 权限表（标记 `is_backup=true`）
  - `Storage::findPermissionByAs608Id(as608Id, perm)` — 验证时按 AS608 物理槽位查找（替代旧 `loadPermission(fpId)` 的指纹ID查找语义）
  - `Storage::listBackupFingerprints()` — 上报本机副指纹清单给上位机
  - `Storage::deleteBackupFingerprint(userId)` — 删除指定用户的本机副指纹
- AS608 ID 分配：`Storage::allocLocalFpId()` — 扫描权限表找未占用的物理槽位（0..FINGER_MAX_USERS-1），优先复用已删除的槽位

### 1.6 副指纹录入流程 — `message_handler.cpp` 新增命令
新增协议命令 `ADD_BACKUP_FINGERPRINT`（见第二部分）：
```cpp
void cmdAddBackupFingerprint(const JsonObject &data, const String &msgId) {
    String userId = data["user_id"];
    // 1. 分配本地 AS608 槽位
    int localId = Storage::allocLocalFpId();
    // 2. 走 enroll 流程录入到该 localId
    enrollFingerprintId = localId;
    enrollUserId = userId;
    enrollIsBackup = true;  // 新增标志
    Fingerprint::enrollBegin(localId);
    setState(STATE_ENROLLING);
}
```
录入完成后：
- 写入本地权限表（`is_backup=true`，`lock_perm` 沿用该用户已有的主指纹权限缓存，或要求上位机附带权限参数）
- 上报 `ADD_FINGERPRINT_RESULT` 含 `is_backup=true, local_fp_id=xxx, user_id=xxx`
- **不修改全局 users 表的 fingerprint_id**（这是副指纹的关键：仅本机生效）

### 1.7 验证流程适配主/副指纹
`STATE_WAIT_FINGER` 中 `verifyFingerprint()` 返回 AS608 物理槽位 ID：
```cpp
int as608Id = Fingerprint::verifyFingerprint();
if (as608Id >= 0) {
    UserPermission perm;
    if (Storage::findPermissionByAs608Id(as608Id, perm) && perm.valid) {
        // 主或副指纹都按 perm.lock_perm 进入 10s 窗口
        verifiedPerms = perm;
        setState(STATE_VERIFIED_WINDOW);
        FpLed::setSuccess();
    } else {
        // 模板存在但权限缓存未同步
        FpLed::setFail();
    }
}
```

### 1.8 `lock_control.cpp` — 开锁时长保持 3s
`LOCK_OPEN_DURATION_MS=3000` 不变（这是继电器物理开锁时长，与 10s 操作窗口无关）。需求中的"10秒操作窗口"是用户验证后选择锁的时间，选定后锁仍开 3s 自动回锁。

### 1.9 `main.cpp` — 主循环调整
- 删除 `STATE_WAIT_FINGER` 由按键触发的逻辑
- `KeyHandler::getKeyPressed()` 在 `STATE_VERIFIED_WINDOW` 时才检查开锁键；在 `STATE_WAIT_FINGER` 时按键忽略（或可设计为"按键也唤醒识别"，但需求要求先验证后按键，故忽略）
- 取消键在所有非 IDLE 状态都生效
- 新增 `FpLed::update()` 调用

## 第三部分：WPF 上位机改造

### 3.1 教师数据范围隔离（G5）— Service 层强制过滤
**当前问题**：`UserService.GetAllUsers()`、`DeviceService`、`LogService` 等都返回全量数据，仅靠 UI 隐藏菜单。教师登录后若直接调用服务仍能拿到其他班级数据。

改造：
- 新增 `Services/IDataScopeContext.cs`：封装当前用户的可见范围（Admin=全部；Teacher=本班 ClassId；Student=仅自己）
- 在 `UserService.GetAllUsers()` 增加 `GetVisibleUsers()` 重载：教师角色自动过滤 `ClassId == currentUser.ClassId`
- `PermissionService`、`LogService`、`FingerprintTemplateService` 同步增加可见范围重载
- `UserManagePage`、`PermissionPage`、`LogPage`、`FingerprintTemplatePage` 改用 `GetVisibleUsers`/`GetVisibleLogs` 等
- `DeviceService`：教师可见全部柜子（设备本身不绑定班级），但只能给自己班级学生分配权限
- **防御性**：在 `UserService.DeleteUser`、`PermissionService.SetUserPermission` 等写操作中加入范围校验，教师尝试操作非本班用户时抛 `UnauthorizedAccessException`

### 3.2 副指纹 UI 流程（G4）— 新增对话框与命令
在 `Views/DevicePage.xaml.cs` 或新建 `Views/BackupFingerprintWindow.xaml`：
- 选择目标用户 + 选择柜子
- 点击"录入本机副指纹"→ 发送 `ADD_BACKUP_FINGERPRINT` → 监听 `ENROLL_PROGRESS` + `ADD_FINGERPRINT_RESULT`
- 录入成功后弹出**二选一对话框**（需求 §2.2）：
  - 选项①"覆盖全局主指纹"：调用 `UserService.AssignFingerprint(userId, newFpId)` 更新 SD 卡 users 表，并 `CabinetSyncService.SyncAllPermissions()` 全局下发
  - 选项②"仅作为本机备用指纹"：不修改 users 表，仅保留柜子本地映射
- 副指纹清单展示：在 `DevicePage` 设备详情区新增"本机副指纹"标签页，发送 `BACKUP_FP_LIST` 拉取并展示
- 删除副指纹：选中条目 → `DELETE_BACKUP_FINGERPRINT` → 柜子本地删除（不影响全局）

## 风险与缓解

1. **存储记录格式升级（12B→16B）的兼容性**：旧柜子升级后首次启动读取 12B 旧记录时，按 `record_size` 字段判断版本并自动迁移（`local_fp_id = fingerprint_id, is_backup = false`），权限版本号 +1 触发上位机重新下发确认。
2. **状态机反转影响现有录入流程**：录入仍走 `STATE_ENROLLING`，与 `STATE_WAIT_FINGER` 并行，互不干扰；录入期间不轮询识别。
3. **双色 LED 硬件未定型**：`led_indicator` 抽象层允许通过 `config.h` 宏切换实现（独立 GPIO / 595 复用 / RGB），先以双独立 GPIO 为默认，硬件定型后调整宏即可。
4. **教师范围过滤的既有数据**：管理员创建的"未绑定班级"用户，教师不可见（符合需求"教师仅管理本班"）；管理员仍可见全部。
5. **副指纹权限继承**：副指纹录入时若上位机未附带权限，沿用柜子本地缓存中该用户主指纹的权限；若本地也无（首次录入即副），提示上位机先同步权限。

## 执行顺序
1. 固件协议层（`config_common.h`、`cmd_ids.h`）→ 2. 固件存储层（`storage.*`）→ 3. 固件状态机与 LED（`message_handler.*`、`led_indicator.*`、`main.cpp`、`config.h`）→ 4. 固件编译验证 → 5. WPF 协议层同步 → 6. WPF 数据范围隔离 → 7. WPF 副指纹 UI → 8. WPF 批量操作与可视化 → 9. WPF 编译与测试 → 10. 文档更新

每完成一个大模块后即时编译验证，避免最后一次性排错。
