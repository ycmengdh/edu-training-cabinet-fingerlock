# 上位机使用说明

## 1. 软件说明

上位机名称为“实训柜指纹权限管理系统”，程序文件为 `CabinetLock.exe`。当前版本为 Windows WPF 应用，主要负责：

- 连接根节点或单台柜机。
- 从根节点 SD 同步集中业务数据。
- 管理用户、老师、班级、角色和个人权限。
- 录入、备份、恢复和下发指纹。
- 管理柜机信息并同步柜机权限。
- 查看操作、通讯和开锁日志。

## 2. 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 x64 |
| 通讯接口 | 根节点 USB 串口，或柜机 UART0 对应的 USB-TTL 串口 |
| 波特率 | 921600，启动页自动使用该值 |
| 目录权限 | 程序所在目录必须可写 |
| 实例数量 | 同一台电脑只允许启动一个上位机实例 |

自包含发布版不需要单独安装 .NET。开发构建版需要 .NET 8 SDK 或相应运行时。

## 3. 启动与连接

### 3.1 组网模式

日常管理多台柜机时使用该模式。

1. 确认根节点、SD 卡和柜机均已通电。
2. 用 USB 数据线连接根节点与电脑。
3. 双击 `CabinetLock.exe`。
4. 选择“组网U盘连接”。
5. 在“选择串口”中选择根节点 COM 口。
6. 等待程序自动完成连接和同步。

程序会优先显示上次成功使用的串口，并根据 USB 设备信息推荐根节点端口。若选错端口，状态区会停留在“等待根节点注册”或提示当前端口类型不符。

> “组网U盘”是产品界面对根节点 USB 设备的称呼，实际通讯方式是 USB 串口，并非磁盘文件访问。

### 3.2 柜机串口直连

检修单台柜机时：

1. 使用 USB-TTL 连接柜机 UART0。
2. 启动上位机并选择“柜机串口直连”。
3. 选择 USB-TTL 对应 COM 口。
4. 等待状态显示“柜机串口直连已就绪”和柜机通讯 ID。

直连模式只操作当前柜机。主窗口顶部会显示“柜机串口直连 · 应急维护模式”提示。现版柜机 UART0 始终可用，无需长按按键切换模式。

### 3.3 启动同步五个阶段

| 阶段 | 程序行为 |
| --- | --- |
| 1 连接 | 打开 COM 口并建立物理链路 |
| 2 就绪 | 等待根节点或柜机协议注册 |
| 3 备份 | 备份当前本机 `business.db` |
| 4 同步 | 组网模式下从 SD 拉取业务表和版本信息 |
| 5 完成 | 切换到登录页 |

同步最多自动重试 3 次。失败时优先执行以下操作：

1. 检查设备供电、USB 数据线和所选 COM 口。
2. 点击“重新连接并同步”。
3. 设备暂时不可用且本机已有可信历史数据时，才选择“仅用本机数据进入登录”。

使用本机数据属于应急模式，不代表 SD 中的最新数据。恢复组网后必须重新完成同步。

## 4. 登录

### 4.1 首次登录

空系统或无可用业务数据时，可使用：

```text
用户 ID：admin
密码：admin123
```

首次进入后点击右上角钥匙图标修改密码。新密码至少 8 个字符。

### 4.2 登录规则

- 管理员和老师账号可登录上位机。
- 学生账号仅用于柜机鉴权，不允许登录上位机。
- 已停用账号无法登录。
- 本机已有业务库时，登录按 `business.db` 中的账号严格校验。
- 默认密码不应被视为永久后门；已有正式账号后使用实际账号密码。

## 5. 主界面

### 5.1 顶部与底部状态

右上角提供：

- 关于软件。
- 浅色/深色主题切换。
- 修改当前账号密码。
- 退出登录。

底部状态栏显示：

- 通讯链路状态。
- 根节点数据/SD 状态。
- 在线柜机数量。
- 待同步任务数量。
- 当前传输方式。
- “立即同步到 SD”按钮。

“物理链路已连接”只代表 COM 口打开；必须继续收到根节点注册并确认 SD 可用，集中数据服务才算正常。

### 5.2 角色可见页面

| 角色 | 可见页面 |
| --- | --- |
| 管理员 | 全部页面 |
| 老师 | 班级管理、系统日志 |
| 学生 | 不允许正常登录；异常已有会话也仅保留系统日志 |

## 6. 功能页面

### 6.1 运行总览

用于快速判断系统是否健康，显示：

- 根节点链路。
- 在线柜机数。
- 权限一致数量。
- 待同步数量。
- 学生绑定情况。
- 当前告警、实时柜机事件和最近开锁记录。

双击柜机相关告警或实时事件可进入对应柜机详情。点击待同步指标可打开同步队列。

### 6.2 用户管理

支持以下操作：

- 添加、编辑和删除用户。
- 重置密码、启用或停用账号。
- 按角色筛选，按姓名、用户 ID 或班级搜索。
- 录入主指纹。
- 从根节点模板恢复指纹到指定柜机。
- 为多名用户批量分配权限。
- 从 UTF-8 CSV 批量导入用户。

删除用户前应确认其班级分配、柜机权限和指纹模板是否仍需保留。修改或删除后要重新同步相关柜机并同步 SD。

### 6.3 老师管理

支持老师账号的添加、编辑、密码重置、启停和删除，还可：

- 录入老师指纹。
- 执行“老师指纹同步”，将老师主指纹和权限同步到目标柜机。
- 设置老师负责班级。

老师应先分配负责班级，再使用老师账号登录；老师登录后只能维护本班学生。

### 6.4 个人权限

左侧选择用户，右侧设置该用户对 `Lock1` 至 `Lock4` 的权限。页面会标出权限来源，例如角色默认或个人设置。

修改个人权限后：

1. 保存权限。
2. 在柜子管理或班级同步窗口同步涉及的柜机。
3. 确认权限版本一致。

### 6.5 角色权限

用于设置管理员、老师和学生的默认锁权限。角色默认值影响该角色下的用户，个人权限可用于例外调整。

修改角色权限的影响范围较大。保存后应同步所有受影响的在线柜机，并检查离线柜机的待同步任务。

### 6.6 班级管理

班级列表支持添加、编辑、启停、删除和打开班级。进入班级后有三个主要工作区：

- “学生名单”：导入/新增学生、连续录指纹、编辑和管理学生。
- “柜机分配”：查看班级对应的柜机以及可使用、待处理人数。
- “同步状态”：按学生和柜机检查当前指纹及权限状态。

“柜机分配同步”窗口支持：

- 选择全部在线柜机。
- 为选中柜机分配整班或取消分配。
- 检测选中柜机差异。
- 同步选中柜机。
- 同步全部已分配柜机。

推荐先“检测选中”，确认需更新数量，再执行同步。

### 6.7 柜子管理

页面显示柜子总数、在线数、已同步数和需处理数。可按设备编号、名称、MAC、通讯 ID 搜索，并按在线、离线、权限落后等状态筛选。

每台柜机提供：

- 同步本柜指纹与权限。
- 修改柜子名称和现场设备编号。
- 打开柜子详情。

设备编号必须唯一，建议使用贴在柜体上的现场编号，例如 `A-01`、`A-02`。通讯 ID 由硬件身份生成，通常形如 `CAB_XXXXXXXXXXXX`，不要把通讯 ID 当作可随意修改的现场名称。

“同步全部柜子”会产生较多通讯，应在链路稳定、所有目标柜机在线时执行。

### 6.8 指纹库

指纹库用于查看用户主指纹模板及备份状态，并执行测试、恢复或删除等操作。录入时按弹窗提示完成多次按压、移开和复核，不要在过程中关闭窗口、拔线或让目标柜机掉电。

系统支持两类指纹：

- 主指纹：集中保存，可同步到多台柜机。
- 设备专属副指纹：在指定柜机录入，只在该柜机生效，用于某台设备识别不稳定时补录。

副指纹录入完成后，根据业务选择“覆盖全局主指纹”或“仅作为本机备用指纹”。不确定时选择本机备用，避免影响其他柜机。

### 6.9 系统日志

系统日志包含三个页签：

| 页签 | 内容 |
| --- | --- |
| 操作日志 | 登录、用户、权限、同步等管理操作 |
| 通讯日志 | 发送、接收和链路状态，用于故障诊断 |
| 开锁日志 | 柜机、用户、锁号、结果和失败原因 |

支持关键词、日期、设备、用户和结果筛选。操作日志、通讯日志和开锁日志均可导出为 XLS。通讯日志“清空缓存”只应用于通讯查看缓存，不应代替业务数据库备份。

## 7. 常用业务流程

### 7.1 新增一个学生并投入使用

1. 在“班级管理”打开目标班级。
2. 点击“新增学生”，填写学号和姓名。
3. 为学生录入主指纹。
4. 点击“批量分配柜机”或进入“柜机分配”。
5. 选择目标柜机并分配。
6. 检测差异并同步选中柜机。
7. 在柜子管理确认权限已同步。
8. 现场测试指纹和对应锁键。
9. 检查开锁日志。
10. 点击“立即同步到 SD”。

### 7.2 批量导入学生

CSV 使用 UTF-8 编码，列顺序固定为：

```csv
user_id,name,role,password,class_id,device_number
S001,张三,student,,CLASS01,A-01
S002,李四,student,,CLASS01,A-02
T001,王老师,teacher,Teacher888,CLASS01,
```

说明：

- `user_id`、`name`、`role`、`password` 为前四列；程序要求至少存在四列。
- 学生密码可为空，学生不登录上位机。
- 管理员和老师密码至少 8 个字符。
- `class_id` 和 `device_number` 可选。
- `role` 使用 `admin`、`teacher` 或 `student`。
- `class_id` 必须已存在。
- `device_number` 填现场设备编号，不填通讯 ID；匹配成功后自动绑定柜机。
- 首行包含 `user_id` 时会自动作为表头跳过。

导入结束后仍需录指纹并同步柜机。

### 7.3 修改权限

1. 在角色权限或个人权限中修改并保存。
2. 打开待同步队列，确认受影响用户和柜机。
3. 目标柜机在线时执行同步。
4. 查看柜子权限版本是否一致。
5. 现场抽测。
6. 同步到 SD。

### 7.4 更换或恢复指纹

1. 确认用户身份和目标柜机。
2. 优先查看指纹库中是否已有可信模板。
3. 有模板时使用“恢复到柜子”；无模板或质量不佳时重新录入。
4. 同步该用户涉及的柜机权限。
5. 现场测试后再删除旧模板。

## 8. 同步和退出

### 8.1 立即同步到 SD

主窗口底部按钮将本机业务库和指纹模板上传到根节点 SD。按钮仅对管理员开放。看到成功提示后才算 SD 已确认接收。

以下情况不要发起同步：

- 根节点数据状态为不可用。
- SD 未就绪。
- USB 链路反复断开。
- 正在录入指纹或正在进行另一项大批量同步。

### 8.2 正常退出

程序检测到本机数据尚未上传时，会打开退出同步窗口并最多尝试 3 次：

- 成功：显示 SD 已确认接收，然后自动退出。
- 失败：可重新上传或取消退出。
- 强制退出：程序生成本地快照并定位 `business.db`；该操作可能导致 SD 缺少本次修改。

不要直接结束进程或关机，否则退出同步和数据库落盘可能无法完成。

## 9. 本机文件

程序运行目录中的主要文件为：

```text
CabinetLock.exe
app_config.json
data/
  business.db
  logs.db
  business.sd-sync
  backups/
    business_yyyyMMdd_HHmmss.bak.db
```

另外，兼容缓存位于：

```text
%APPDATA%\CabinetLock\cache\
```

备份或迁移上位机时，至少保留整个 `data` 目录和 `app_config.json`。复制数据库前应正常退出程序。

## 10. 常见提示

| 提示 | 含义与处理 |
| --- | --- |
| 物理链路未连接 | 检查 USB、COM 口、驱动和串口占用 |
| 已连接，尚未收到根节点协议帧 | 端口可能选错，或根节点固件未正常运行 |
| SD 卡未就绪 | 检查卡、格式和根节点接线；不要继续覆盖数据 |
| 权限落后 | 柜机本地版本低于上位机，应重新同步该柜 |
| 待同步 | 有指纹或权限任务尚未完成，打开队列查看原因 |
| 仅用本机数据 | 应急模式，数据可能不是 SD 最新版本 |
| 数据版本冲突 | 两边都可能有修改，先备份，不要盲目覆盖 |
