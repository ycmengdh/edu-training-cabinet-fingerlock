# 系统使用说明

## 1. 系统用途

本系统用于学校实训柜的指纹身份验证、四路柜锁控制和集中权限管理。管理员通过 Windows 上位机管理用户、班级、指纹、柜机和权限；各柜机在本地完成指纹匹配和权限判断，因此上位机或 Mesh 短时离线时，已经同步的权限仍可使用。

## 2. 系统组成

```text
Windows 上位机
    │ USB 串口 921600
    ▼
根节点 ESP32-S3 N16R8
    ├─ SD 卡：集中业务数据
    ├─ TFT：运行状态
    └─ ESP-MESH
         ├─ 柜机 1：指纹模块 + 4 路锁 + 5 个按键
         ├─ 柜机 2：指纹模块 + 4 路锁 + 5 个按键
         └─ 柜机 N
```

单柜检修时可使用 USB-TTL 直接连接柜机 UART0：

```text
Windows 上位机 ── USB-TTL 921600 ── 柜机 GPIO43/44
```

| 组件 | 主要职责 |
| --- | --- |
| 上位机 | 管理业务数据、下发指纹和权限、查看状态与日志 |
| 根节点 | 汇聚 Mesh、转发命令、保存 SD 数据、显示系统状态 |
| 柜机 | 本地识别指纹、校验权限、控制 4 路锁、缓存离线日志 |
| SD 卡 | 保存用户、班级、权限、设备、指纹模板和版本信息 |

## 3. 使用前检查

### 3.1 硬件检查

- 根节点、柜机和锁电源规格正确，接线牢固。
- 根节点 SD 卡已插入并可用。
- 根节点通过可传输数据的 USB 线连接电脑。
- 柜机指纹模块、按键、74HC595 和继电器接线正确。
- 首次部署时，所有柜机和根节点使用相同 Mesh 参数，当前默认信道为 `6`。

### 3.2 电脑检查

- 使用 Windows 10/11 x64。
- 设备管理器中能看到根节点或 USB-TTL 的 COM 口。
- 同一时刻只有一个程序占用该 COM 口；关闭串口监视器和调试脚本。
- 上位机目录可写，因为配置和数据库位于程序目录内。

## 4. 标准开机流程

1. 在断电状态下插好根节点 SD 卡。
2. 接通根节点电源。
3. 接通各柜机电源。
4. 等待约数秒至数十秒，让 Mesh 完成组网。
5. 查看根节点屏幕，确认 SD 和 Mesh 状态正常。
6. 将根节点 USB 接到电脑，启动上位机。
7. 在启动页选择“组网U盘连接”和正确 COM 口。
8. 等待业务数据从 SD 同步至本机后登录。
9. 在“运行总览”和“柜子管理”确认在线柜机数量正确。

若上位机已经启动但未识别新插入的串口，点击启动页串口框右侧的刷新按钮。

## 5. 根节点屏幕说明

根节点使用 160×80 横屏状态台，页面约每 7 秒轮播一次。

### 5.1 顶栏

| 显示 | 含义 |
| --- | --- |
| `ROOT` | 当前设备为根节点 |
| `00:12`、`1d03` | 运行时长；分别表示 12 分钟、1 天 3 小时 |
| `USB` / `AP` / `STA` | 当前上行方式 |
| 状态后带 `!` | 上行链路未连接 |
| `1/3`、`2/3`、`3/3` | 当前轮播页，固定显示在右上角，与 USB 状态分开 |

### 5.2 三个状态页

| 页码 | 典型显示 | 说明 |
| --- | --- | --- |
| 1/3 | `CAB 5/6`、`SD OK`、`M2` | 在线/已知柜机数、SD 状态、Mesh 及子节点数 |
| 2/3 | `H...k SD...% L...` | 可用内存、SD 使用率、Mesh 层级和链路信息 |
| 3/3 | `V... CH06 ID:...` | 固件版本、Mesh 信道、根节点 ID；末尾 `!` 表示时间未同步 |

屏幕底部四行显示最近事件。绿色通常表示成功，红色表示错误或告警。出现 `SD!`、`M!`、`USB!` 时，应先检查对应硬件或链路。

## 6. 柜机日常开锁

当前柜机使用“先验证指纹，再选择锁”的流程：

1. 将已录入的手指平稳放在指纹传感器上。
2. 指纹匹配且本机存在有效权限后，柜机进入约 10 秒操作窗口。
3. 有权限的锁指示灯闪烁提示可选锁。
4. 在 10 秒内按 `K1` 至 `K4`，分别控制 `Lock1` 至 `Lock4`。
5. 对应继电器动作约 1 秒后自动关闭；硬件保护最迟约 2 秒强制关闭。
6. 若不需要开锁，按 `K5` 取消；超时也会自动退出本次验证。

以下情况不会开锁：

- 指纹未录入或识别失败。
- 指纹已录入，但该用户没有当前柜机或当前锁权限。
- 权限已过期、被停用或尚未同步到该柜机。
- 按下了不在本次权限范围内的锁键。

柜机断网时仍使用本地权限缓存完成验证。断网期间产生的日志保存在 Flash 中，网络恢复后继续上报。

## 7. 用户角色

| 角色 | 上位机权限 | 柜机权限特点 |
| --- | --- | --- |
| 管理员 `admin` | 所有管理页面和全局数据 | 由角色默认和个人权限共同决定 |
| 老师 `teacher` | 班级管理、系统日志；仅管理负责班级 | 主指纹可按业务流程同步到所需柜机 |
| 学生 `student` | 不允许登录上位机 | 仅使用分配给自己的柜机和锁权限 |

角色默认权限在“角色权限”中设置，针对单个用户的例外在“个人权限”中设置。最终生效结果以同步到柜机的权限为准。

## 8. 推荐业务配置顺序

首次部署建议严格按以下顺序操作：

1. 在“柜子管理”为每台在线柜机设置唯一的设备编号和易识别的名称。
2. 在“角色权限”确认管理员、老师、学生的默认锁权限。
3. 在“班级管理”创建班级。
4. 在“老师管理”创建老师账号，并分配负责班级。
5. 在班级工作台新增或导入学生。
6. 为老师和学生录入主指纹。
7. 在“个人权限”设置必要的个人例外权限。
8. 在班级的“柜机分配同步”中分配柜机。
9. 执行“检测选中”后再“同步选中”或“同步全部已分配柜机”。
10. 在“柜子管理”确认权限状态为已同步。
11. 逐人现场测试开锁，并在“系统日志 → 开锁日志”核对记录。
12. 点击“立即同步到 SD”保存本次业务变更。

## 9. 数据同步规则

系统有三个数据层次：

```text
根节点 SD（集中数据）
       ↕ 启动拉取 / 手动或退出时回写
上位机 business.db（运行期间工作副本）
       ↓ 按柜下发
柜机 NVS/Flash（指纹权限和离线日志）
```

- 启动上位机时，程序先备份本机库，再从 SD 拉取业务表。
- 上位机中的业务编辑先写本机数据库，不等于已经写入 SD 或柜机。
- “立即同步到 SD”负责把本机集中业务数据回写根节点。
- “同步柜机”负责把相关指纹和权限下发到具体柜机。
- 两类同步缺一不可：写入 SD 不能替代柜机同步，柜机同步也不能替代 SD 备份。

## 10. 单柜串口维护

单柜 UART 用于产测、修柜或 Mesh 异常时的应急维护。

1. 使用 3.3V 电平 USB-TTL。
2. 连接 `USB-TTL TX → 柜机 GPIO44(RX)`、`USB-TTL RX ← 柜机 GPIO43(TX)` 和公共 `GND`。
3. 启动上位机，选择“柜机串口直连”。
4. 选择 USB-TTL 对应 COM 口，等待显示柜机通讯 ID。
5. 登录后只操作当前直连柜机。

当前固件固定为 `Mesh + UART0` 同时运行，不需要长按按键切换，也不会因接入 UART 自动退出 Mesh。

直连期间的业务变更主要保存在本机；恢复组网连接时，先按启动页提示检查 SD 版本并完成同步。若提示版本冲突，不要强制覆盖，应先备份 `business.db`，确认哪一份数据更新后再处理。

## 11. 标准关机流程

1. 停止继续修改用户、权限或指纹。
2. 查看主窗口底部“待同步”数量并处理未完成任务。
3. 点击“立即同步到 SD”，等待成功提示。
4. 正常关闭上位机。
5. 若退出窗口再次上传业务数据，等待“SD 已确认接收”后再退出。
6. 上位机关闭后再拔 USB。
7. 确认根节点无写卡操作后再断电或拔 SD 卡。

退出上传失败时，优先选择“取消退出”或“重新上传”。只有明确接受 SD 中缺少本次修改时才使用“不上传，强制退出”，并按程序提示备份本机数据库。

## 12. 日常检查清单

- 根节点屏幕无 `SD!`、`M!`、`USB!`。
- 上位机底部显示链路和根节点数据正常。
- 在线柜机数量与现场通电数量一致。
- 柜机权限版本无“落后”或“需要处理”。
- 待同步队列为 0。
- 抽查一名老师和一名学生的指纹开锁。
- 开锁日志能正常显示，时间正确。
- 完成业务修改后已同步到 SD。
