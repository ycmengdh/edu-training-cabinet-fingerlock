# 安装部署与维护

## 1. 适用范围

本文供设备安装、固件烧录、上位机部署、现场联调和故障维护使用。所有参数以当前源码为准：

- 上位机：`CabinetLock/`
- 根节点：`esp32_firmware/root_node/`
- 柜机：`esp32_firmware/cabinet_node/`
- 公共协议：`esp32_firmware/common/`

当前硬件基线为 ESP32-S3 N16R8，即 16 MB Flash、8 MB PSRAM。

## 2. 部署拓扑

### 2.1 正常多柜部署

```text
Windows 电脑
    │ USB 数据线，921600
    ▼
根节点（USB CDC + SD + TFT）
    │ ESP-MESH，默认信道 6
    ├── 柜机 A
    ├── 柜机 B
    └── 柜机 N
```

### 2.2 单柜维护

```text
Windows 电脑
    │ USB-TTL，921600，3.3V TTL
    ▼
柜机 UART0
    TX GPIO43 → USB-TTL RX
    RX GPIO44 ← USB-TTL TX
    GND       ─ USB-TTL GND
```

当前柜机固件同时维护 Mesh 和 UART0，不存在必须先切换到 Debug 模式的步骤。历史资料中“长按任意键 10 秒切换模式”的说明不适用于当前实现。

## 3. 安全要求

- 接线、插拔 SD 卡和调整继电器线路前先断电。
- USB-TTL 的 IO 电平必须兼容 3.3V，禁止将 5V 信号直接接入 ESP32 GPIO。
- USB-TTL 与柜机必须共地，TX/RX 必须交叉连接。
- 锁电源与 ESP32 电源按硬件设计隔离或共地，不得让继电器反向电动势进入控制板。
- 不要在固件烧录、SD 写入、指纹录入或业务同步时断电。
- GPIO45 是 ESP32-S3 启动相关引脚，K3 外围不要增加会在复位时强拉电平的电路。

## 4. 根节点安装

### 4.1 外设引脚

| 外设 | 信号 | GPIO |
| --- | --- | --- |
| TFT ST7735 | MOSI | 11 |
| TFT ST7735 | SCLK | 10 |
| TFT ST7735 | CS | 12 |
| TFT ST7735 | DC | 13 |
| TFT ST7735 | RST | 14 |
| SD_MMC 1-bit | CLK | 17 |
| SD_MMC 1-bit | CMD | 18 |
| SD_MMC 1-bit | D0 | 16 |

根节点通过 ESP32-S3 USB-Serial-JTAG/CDC 与上位机通信，波特率为 `921600`。根节点没有指纹、按键、锁或柜机状态 LED。

### 4.2 SD 卡准备

1. 使用质量可靠的 SD/SDHC 卡，建议在电脑上格式化为 FAT32。
2. 在根节点断电时插卡。
3. 上电后观察屏幕是否出现 `SD OK`。
4. 首次使用时，固件会自动创建 `/data`、`/data/fingerprints` 及初始业务表。

固件挂载失败时会自动尝试 20 MHz、4 MHz 和 1 MHz，但不会自动格式化 SD 卡。这样可避免因挂载异常误删用户数据。

SD 卡主要目录如下：

```text
/data/
  version.json
  users.json
  classes.json
  permissions.json
  role_permissions.json
  fingerprints.json
  devices.json
  fingerprints/
```

### 4.3 根节点验收

- 开机屏显示 `ROOT BOOT`。
- SD 正常时显示 `SD READY`，进入状态台后显示 `SD OK`。
- USB 接入上位机后，顶栏显示 `USB`，不带 `!`。
- 有柜机入网后，`CAB` 在线数量和 `M` 状态变化。
- 屏幕右上角页码独立显示 `1/3` 至 `3/3`。

## 5. 柜机安装

### 5.1 当前源码引脚

| 模块 | 信号 | GPIO | 说明 |
| --- | --- | --- | --- |
| UART0 | TX | 43 | 接 USB-TTL RX |
| UART0 | RX | 44 | 接 USB-TTL TX |
| AS608 | ESP TX | 17 | 接指纹模块 RX |
| AS608 | ESP RX | 18 | 接指纹模块 TX |
| AS608 | 电源控制 | 21 | 当前为低电平有效上电 |
| AS608 | 电源状态 | 42 | 当前按高电平表示已上电 |
| 74HC595 | DS | 4 | 串行数据 |
| 74HC595 | STCP | 15 | 锁存时钟 |
| 74HC595 | SHCP | 16 | 移位时钟 |
| 按键 K1 | Lock1 | 47 | 低电平按下 |
| 按键 K2 | Lock2 | 48 | 低电平按下 |
| 按键 K3 | Lock3 | 45 | 低电平按下，启动相关脚 |
| 按键 K4 | Lock4 | 38 | 低电平按下 |
| 按键 K5 | 取消 | 39 | 低电平按下 |
| 状态 LED | Mesh 状态 | 2 | 非锁指示灯 |

> 若 PCB 丝印或旧文档与此表冲突，先核对当前 `cabinet_node/src/config.h` 和实际板卡版本，不要带电试错。

### 5.2 74HC595 输出

| 输出 | 当前用途 |
| --- | --- |
| Q0 / OUT1 | Lock4 继电器 |
| Q1 / OUT2 | Lock3 继电器 |
| Q2 / OUT3 | Lock2 继电器 |
| Q3 / OUT4 | Lock1 继电器 |
| Q4 / OUT5 | Lock1 权限/状态 LED |
| Q5 / OUT6 | Lock2 权限/状态 LED |
| Q6 / OUT7 | Lock3 权限/状态 LED |
| Q7 / OUT8 | Lock4 权限/状态 LED |

继电器和 LED 均按高电平有效设计。开锁动作通常保持 1 秒，连续激活超过 2 秒时固件强制关闭继电器。

### 5.3 柜机验收

1. 上电后 UART0 能看到 `CABINET_BOOT` 和 `PROTOCOL READY` 启动标记。
2. 上位机能识别形如 `CAB_XXXXXXXXXXXX` 的唯一通讯 ID。
3. 柜机能加入根节点 Mesh，并出现在“柜子管理”。
4. AS608 初始化成功，可完成录入和匹配。
5. K1 至 K4 与 Lock1 至 Lock4 一一对应，K5 可取消验证。
6. 指纹验证后，有权限锁 LED 闪烁，按键后对应继电器动作约 1 秒。
7. 断开 Mesh 后，已同步权限仍可开锁；断链期间开锁日志不保存，恢复后新事件即时上报。
8. 保持 Mesh、关闭上位机后执行开锁；重新启动上位机，确认根节点暂存日志自动进入 `logs.db`，随后根节点 `/data/logs` 待同步文件被清除。

## 6. 固件开发环境

### 6.1 安装

准备以下工具：

- Python 3。
- PlatformIO Core，或 VS Code PlatformIO 插件。
- 支持数据传输的 USB 线和正确的串口驱动。

首次构建需要联网下载 ESP32 平台、Arduino 框架和依赖库。更换开发电脑的详细说明见 [换开发电脑说明](../../esp32_firmware/换开发电脑说明.md)。

### 6.2 编译根节点

```powershell
cd esp32_firmware/root_node
pio run
```

### 6.3 编译柜机

```powershell
cd esp32_firmware/cabinet_node
pio run
```

### 6.4 查看串口和烧录

```powershell
pio device list
pio run -t upload --upload-port COM5
```

将 `COM5` 替换为实际端口。两个固件工程必须分别进入自己的目录烧录，不能把根节点固件烧到柜机。

烧录后可监视启动输出：

```powershell
pio device monitor --port COM5 --baud 921600
```

监视器会占用串口。启动上位机前必须关闭监视器。

### 6.5 固件产物

构建成功后，主要产物位于：

```text
esp32_firmware/root_node/.pio/build/root/
esp32_firmware/cabinet_node/.pio/build/cabinet/
```

保留发布版本的 `firmware.bin`，并同时记录源码提交、固件版本、分区表和烧录日期。仅保存一个 bin 不足以完整恢复整片 Flash 的分区数据。

## 7. 上位机开发与发布

### 7.1 开发环境

- Windows 10/11 x64。
- .NET 8 SDK。
- Visual Studio 2022，或直接使用 `dotnet` CLI。

### 7.2 编译

在仓库根目录执行：

```powershell
dotnet restore CabinetLock/CabinetLock.sln
dotnet build CabinetLock/CabinetLock.sln -c Release
```

### 7.3 运行测试

```powershell
dotnet test CabinetLock/CabinetLock.Tests/CabinetLock.Tests.csproj -c Release
```

### 7.4 发布独立版

```powershell
dotnet publish CabinetLock/CabinetLock/CabinetLock.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true
```

项目已配置为单文件、自包含发布。典型输出目录为：

```text
CabinetLock/CabinetLock/bin/Release/net8.0-windows/win-x64/publish/
```

部署时将整个发布目录放到可写位置，例如 `D:\CabinetLock`。不建议直接放入受保护的 `Program Files`，因为程序会在运行目录创建 `app_config.json` 和 `data`。

### 7.5 首次运行

1. 将发布目录复制到目标电脑。
2. 安装根节点或 USB-TTL 所需驱动。
3. 连接设备，确认设备管理器出现 COM 口。
4. 运行 `CabinetLock.exe`。
5. 允许程序在本机目录创建配置和数据文件。
6. 首次登录后修改默认管理员密码。

若使用 TCP 客户端/服务端传输，Windows 防火墙可能需要允许相应端口。当前标准启动页面向 USB 串口部署，现场日常使用优先采用 USB。

## 8. 初次部署流程

### 8.1 烧录和标识

1. 烧录根节点固件并贴上“ROOT”标签。
2. 逐台烧录柜机固件。
3. 记录每台柜机通讯 ID、MAC、柜体位置和计划设备编号。
4. 检查所有设备固件版本一致。

### 8.2 硬件联调

1. 单独验证根节点 TFT 和 SD。
2. 单独验证每台柜机的指纹、按键、锁和 UART0。
3. 接通 Mesh，确认所有柜机陆续在线。
4. 检查同一教室内设备使用相同信道和 Mesh 参数。

### 8.3 业务初始化

1. 启动上位机并从 SD 同步。
2. 使用首次管理员账号登录并修改密码。
3. 设置柜机名称和唯一设备编号。
4. 配置角色权限。
5. 建立班级、老师和学生。
6. 录入指纹并完成柜机分配同步。
7. 逐台、逐锁抽测。
8. 同步到 SD并正常退出。

## 9. 数据备份

### 9.1 上位机数据

正常退出上位机后，备份以下内容：

```text
app_config.json
data/business.db
data/logs.db
data/backups/
```

`business.db` 是运行期间的业务工作副本，`logs.db` 保存本机操作和开锁日志，`data/backups` 保存启动同步前的历史快照。

根节点 SD 的 `/data/logs/YYYY-MM-DD.jsonl` 只是在上位机离线期间的待同步区，最多保留 30 天。正常退出只回写业务数据，不会把上位机 `logs.db` 上传到 SD。

推荐按日期将整个程序目录复制到独立磁盘。数据库正在使用时不要直接复制，以免只复制到未完成的 WAL 状态。

### 9.2 SD 卡数据

1. 先在上位机执行“立即同步到 SD”。
2. 正常退出上位机。
3. 根节点断电后取出 SD 卡。
4. 将 SD 卡完整复制到备份目录。
5. 将 SD 卡安全弹出，再插回断电的根节点。

不要只备份单个 JSON；版本文件、指纹目录和各业务表必须保持同一时间点的一致性。

## 10. 升级建议

1. 记录当前上位机、根节点和柜机版本。
2. 完成上位机数据库与 SD 卡双重备份。
3. 在一套测试设备上验证新版本。
4. 先升级根节点，再分批升级柜机，最后发布匹配的上位机。
5. 升级后检查注册、SD、版本、指纹、权限、开锁和日志全流程。
6. 不要在没有回退固件和数据备份的情况下批量升级现场设备。

若新版本涉及协议或数据结构变更，三个组件应作为同一发布批次管理。

## 11. 故障排查

### 11.1 上位机找不到串口

1. 换用确认可传数据的 USB 线。
2. 在设备管理器查看是否出现 COM 口或未知设备。
3. 安装对应 USB CDC、CH340、FTDI 或 CP210x 驱动。
4. 关闭 PlatformIO 监视器、串口助手和其他上位机实例。
5. 点击启动页刷新串口。
6. 拔插设备并重新选择端口。

### 11.2 COM 已打开但无协议响应

- 组网模式可能选到了 USB-TTL，直连模式可能选到了根节点。
- 确认波特率为 921600。
- 查看设备是否持续重启。
- 根节点检查屏幕和启动日志；柜机检查 UART0 的 `PROTOCOL READY`。
- 柜机直连检查 TX/RX 是否交叉、是否共地。

### 11.3 根节点显示 `SD!` 或 `SD UNAVAILABLE`

1. 断电后重插 SD 卡。
2. 用电脑读取并立即备份可恢复数据。
3. 检查 FAT32 格式和卡的健康状态。
4. 核对 CLK=17、CMD=18、D0=16。
5. 换一张质量可靠的 SD 卡测试。
6. 查看串口日志中的 `ROOT_SD_FAIL` 阶段信息。

固件不会自动格式化挂载失败的卡，因此不要期待重新上电会清空并修复文件系统。

### 11.4 柜机不在线

- 确认柜机供电稳定，GPIO2 状态 LED工作。
- 检查根节点是否正常作为 Mesh Root。
- 核对 Mesh 信道和密码。
- 查看是否有重复通讯 ID；正常 ID 应由 MAC 生成。
- 将柜机靠近根节点测试，排除距离和干扰。
- 使用 UART0 直连读取启动与 Mesh 日志。

### 11.5 指纹无法初始化

- 检查 ESP TX17 → 模块 RX、ESP RX18 ← 模块 TX。
- 检查共地和模块电源规格。
- 核对 GPIO21 电源控制及 GPIO42 状态反馈。
- 确认 UART2 波特率 57600。
- 观察上电后是否完成多次初始化重试。

### 11.6 指纹识别成功但不能开锁

1. 确认是否进入 10 秒窗口、对应锁 LED 是否闪烁。
2. 在上位机检查用户、柜机和锁权限。
3. 检查柜机权限是否已同步且版本一致。
4. 确认按键与 Lock1 至 Lock4 映射正确。
5. 检查 74HC595 和继电器接线。
6. 查看开锁日志中的失败原因。

### 11.7 继电器一直吸合

立即切断锁驱动电源，然后检查：

- 74HC595 输出极性和继电器板有效电平。
- Q0 至 Q3 与 Lock4 至 Lock1 的反向排列是否接错。
- DS、STCP、SHCP 接线。
- 是否烧录了当前柜机固件。

当前固件有 2 秒强制关断保护，但不能替代硬件安全设计。

### 11.8 数据同步失败或版本冲突

- 先备份 `data/business.db` 和 SD 卡。
- 确认当前连接的是根节点，不是柜机直连端口。
- 检查根节点 SD 和 USB 链路稳定性。
- 使用启动页重试，不要反复强制退出。
- 直连期间发生过本机修改时，先判断本机与 SD 哪边更新。
- 未确认数据来源前，不要手工替换 JSON 或强制覆盖版本。

### 11.9 日志时间不正确

- 检查根节点或柜机时间同步状态。
- 检查 Windows 系统时间和时区。
- 根节点屏幕身份页末尾 `!` 表示时间未同步。
- 离线期间日志可能先使用设备本地时间，联网后再恢复同步。
