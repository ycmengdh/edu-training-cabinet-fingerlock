# 系统架构与组网说明

更新时间：2026-07-28  
本文是**当前实现**的权威摘要；与早期「柜机 WiFi/TCP 直连上位机」「调试模式 AP+TCP」等草案描述冲突时，**以本文为准**。

---

## 1. 硬件基线

| 项目 | 现状 |
| --- | --- |
| 主控 | **ESP32-S3 N16R8**（16MB Flash + 8MB Octal PSRAM） |
| 根节点 / 柜机 | 同一芯片规格；外设不同（根节点：TFT + SD；柜机：指纹 + 按键 + 锁） |
| 工程配置 | `platformio.ini` 使用 `board_build.flash_size = 16MB`、`qio_opi`、公共分区表 `common/partitions_16MB_log.csv` |
| 指纹 | AS608（柜机 UART2） |
| 锁 | 4 路继电器，经 74HC595 扩展 |
| 按键 | 5 路（4 开锁 + 1 取消 / 长按切模式） |

> 不再按 N8（8MB Flash）规划；分区与日志偏移均按 **16MB** 模组落地。

---

## 2. 总体拓扑

日常多柜运行走 **ESP-MESH**；根节点再经 USB 串口接到上位机。  
单柜开发 / 检修时，**仍保留柜机 UART0 直连上位机**，协议与根节点上行一致，可独立控制该柜。

```text
┌────────────────────┐
│  上位机 (WPF)      │
│  business.db 工作副本│
└─────────┬──────────┘
          │  主路径：USB 串口 921600（接根节点）
          │  辅路径：USB-TTL 921600（接单台柜机 UART0）
          ▼
┌────────────────────┐          ESP-MESH 自组网
│  根节点 Root       │◄──────────────────────────────┐
│  Mesh 汇聚 + SD    │                               │
│  （可选 AP/STA 上行）│                               │
└─────────┬──────────┘                               │
          │                                          │
   ┌──────┴──────┬──────────────┐                    │
   ▼             ▼              ▼                    │
┌──────┐     ┌──────┐      ┌──────┐                  │
│柜机 1│ ... │柜机 N│      │柜机 M│── UART0 直连 ────┘（单台维护时）
│指纹锁│     │指纹锁│      │指纹锁│
└──────┘     └──────┘      └──────┘
```

**数据权威链**：

```text
柜机本地鉴权（NVS 权限缓存）
    → 日志经 Mesh 到根节点
    → 根节点 SD（JSON 业务表，权威源）
    ↔ 上位机 business.db（启动拉 / 退出或手动推）
```

鉴权**不依赖**上位机在线；上位机离线只影响管理与展示。

## 3. 两种通讯模式（并存）

### 3.1 Mesh 模式（默认，多柜部署）

| 项目 | 说明 |
| --- | --- |
| 用途 | 实训室多柜日常运行 |
| 组网 | ESP-MESH 树状自组网，柜机找 Root |
| 上位机接入 | **只接根节点**（USB-Serial-JTAG / CDC，921600） |
| 柜机侧 | 默认 **Mesh + UART0 协议口同时开着**（UART0 可用于旁路监听/紧急直连，业务主路径仍走 Mesh） |
| 路由 | 上位机按 `device_id` 发命令 → Root 查 Mesh MAC → 单播到目标柜 |
| 协议 | 外层 A5/5A 帧（上行）+ 应用层 B1/0F 二进制信封；Mesh 上可直接传应用信封 |

### 3.2 单柜 UART 模式（Debug / 单台控制）

| 项目 | 说明 |
| --- | --- |
| 用途 | 单台柜机开发、联调、无 Mesh 环境维护 |
| 物理口 | 柜机 **UART0：TX=GPIO43，RX=GPIO44**，外接 USB-TTL |
| 波特率 / 协议 | **与根节点 USB 上行相同**（921600 + A5/5A + B1/0F） |
| 进入方式 | 任意键**长按约 10s** 切换 `MODE_MESH` ↔ `MODE_DEBUG`，重启生效 |
| Debug 行为 | **不组 Mesh**，仅 UART0；周期 `REGISTER`（`uplink=uart0`, `role=cabinet`） |
| 上位机 | 打开对应 COM，按「接根节点」同样的帧协议，对**该柜 `device_id`** 下发命令 |

> **不是** AP 热点 + TCP。单台通讯控制走的是 **UART 串口协议**，与历史草案中的「调试模式 AP+TCP」不同。

模式对照：

| | Mesh 模式 | 单柜 UART（Debug） |
| --- | --- | --- |
| 无线 | ESP-MESH 组网 | 不组网 |
| 上位机接哪里 | 根节点 USB | 该柜 UART0（USB-TTL） |
| 可同时管多柜 | 是 | 否（当前串口只服务这一台） |
| 柜机本地开锁 | 正常 | 正常 |
| 典型场景 | 教室部署 | 产测 / 修柜 / 单机脚本 |

接线与切换细节见 `esp32_firmware/doc/柜子/IO分配.md`。  
压测脚本见 `debug/README.md`（`--links mesh` / `--links uart`）。

## 4. 根节点上行可选方式

根节点 ↔ 上位机除默认 **USB 串口** 外，工程仍支持：

- **USB Serial**（推荐默认）
- **WiFi AP + TCP**（根节点开热点，PC 连入）
- **WiFi STA + TCP**（根节点连路由器，PC 作服务端或客户端）

由上位机 `MeshBridge` + `ITransport` 切换。  
**柜机之间不直连 PC 的 WiFi/TCP**；多柜统一经 Mesh 到 Root。

## 6. 部署心智模型（一句话）

**芯片统一 N16R8；教室里用 Mesh 管一群柜，修一台柜就用 UART 直连，协议同一套。**
