# ESP32指纹锁实训柜权限管理系统 - 功能与方案文档

## 1. 项目概述

### 1.1 项目背景

本项目是针对学校实训场景设计的实训柜指纹权限管理系统。每个实训柜配备一个ESP32模块和指纹模块组成的指纹锁，通过WiFi与上位机进行通信，实现指纹权限的远程管理和分配。

### 1.2 项目目标

- 实现基于指纹识别的实训柜门锁控制
- 建立三级权限管理体系（系统管理员/老师/学生）
- 支持远程权限分配和管理
- 确保系统安全性和可靠性

### 1.3 应用场景

学校实训室中，每个实训柜配备一套指纹锁系统，学生和老师通过指纹识别打开对应的柜门，系统管理员负责整体权限管理。

## 3. 权限管理方案

### 3.1 权限等级定义

| 权限等级 | 角色名称 | 权限描述 | 系统锁权限 |
| :--- | :--- | :--- | :--- |
| Level 1 | 系统管理员 | 可开启所有4个锁 | **有** |
| Level 2 | 老师 | 可开启除系统锁外的所有锁 | **无**（默认） |
| Level 3 | 学生 | 由老师分配指定锁的权限 | **无**（默认） |

### 3.2 锁编号规则

| 锁编号 | 锁名称 | 说明 |
| :--- | :--- | :--- |
| Lock 0 | 系统锁 | 仅系统管理员可开启 |
| Lock 1 | 实训柜1 | 老师和授权学生可开启 |
| Lock 2 | 实训柜2 | 老师和授权学生可开启 |
| Lock 3 | 实训柜3 | 老师和授权学生可开启 |

### 3.3 权限矩阵

| 角色 | Lock 0 (系统锁) | Lock 1 | Lock 2 | Lock 3 |
| :--- | :--- | :--- | :--- | :--- |
| 系统管理员 | ✅ | ✅ | ✅ | ✅ |
| 老师 | ❌ | ✅ | ✅ | ✅ |
| 学生（未授权） | ❌ | ❌ | ❌ | ❌ |
| 学生（授权Lock1） | ❌ | ✅ | ❌ | ❌ |
| 学生（授权Lock1+Lock2） | ❌ | ✅ | ✅ | ❌ |

### 3.4 权限数据结构

```json
{
  "user_id": "U001",
  "role": "student",
  "fingerprint_id": 1,
  "lock_permissions": {
    "lock_0": false,
    "lock_1": true,
    "lock_2": false,
    "lock_3": true
  },
  "name": "张三",
  "create_time": "2024-01-01 00:00:00"
}
```

## 5. 通信协议设计

### 5.1 通信方式

- **协议**: TCP/IP
- **端口**: 8888（可配置）
- **连接方式**: 下位机主动连接上位机

### 5.2 数据格式

采用JSON格式进行数据传输，每个数据包包含以下字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `cmd` | string | 命令类型 |
| `device_id` | string | 设备唯一标识 |
| `data` | object | 数据内容 |
| `timestamp` | string | 时间戳 |
| `checksum` | string | 校验和 |

### 5.3 命令列表

#### 5.3.1 下位机 → 上位机

| 命令 | 说明 | 数据结构 |
| :--- | :--- | :--- |
| `REGISTER` | 设备注册 | `{"device_name": "实训柜1"}` |
| `FINGER_VERIFY` | 指纹验证请求 | `{"fingerprint_id": 1}` |
| `STATUS_REPORT` | 状态上报 | `{"online": true, "lock_status": [0, 0, 0, 0]}` |
| `LOG_REPORT` | 日志上报 | `{"user_id": "U001", "lock_id": 1, "action": "open", "time": "2024-01-01 00:00:00"}` |

#### 5.3.2 上位机 → 下位机

| 命令 | 说明 | 数据结构 |
| :--- | :--- | :--- |
| `AUTH_OK` | 验证成功 | `{"permissions": {"lock_0": true, "lock_1": true, "lock_2": true, "lock_3": true}}` |
| `AUTH_FAIL` | 验证失败 | `{"reason": "用户不存在或权限不足"}` |
| `SYNC_PERMISSIONS` | 同步权限 | `{"users": [...], "timestamp": "2024-01-01 00:00:00"}` |
| `ADD_FINGERPRINT` | 添加指纹 | `{"user_id": "U001", "fingerprint_id": 1, "template": "..."}` |
| `DELETE_FINGERPRINT` | 删除指纹 | `{"fingerprint_id": 1}` |
| `CONTROL_LOCK` | 控制锁 | `{"lock_id": 1, "action": "open"}` |

### 5.4 通信流程

#### 5.4.1 指纹验证流程

```
下位机                    上位机
  │                         │
  │── FINGER_VERIFY ───────►│
  │  (fingerprint_id)       │
  │                         │
  │                         ▼
  │                    查询用户权限
  │                         │
  │◄── AUTH_OK ─────────────│
  │  (permissions)          │
  │                         │
  ▼                         │
 根据权限控制锁
```

#### 5.4.2 权限同步流程

```
上位机                    下位机
  │                         │
  │── SYNC_PERMISSIONS ────►│
  │  (users, timestamp)     │
  │                         │
  │◄── SYNC_ACK ────────────│
  │                         │
```

## 7. 硬件设计

### 7.1 硬件连接图

```
ESP32-WROOM-32
├── UART2 (TX: GPIO17, RX: GPIO16)
│   └── AS608指纹模块
│       ├── VCC: 3.3V
│       ├── GND: GND
│       ├── TX: GPIO16 (ESP32 RX)
│       └── RX: GPIO17 (ESP32 TX)
│
├── GPIO输出 (继电器控制)
│   ├── GPIO23 → 继电器1 (Lock 0)
│   ├── GPIO22 → 继电器2 (Lock 1)
│   ├── GPIO21 → 继电器3 (Lock 2)
│   └── GPIO19 → 继电器4 (Lock 3)
│
├── GPIO输入 (按键)
│   ├── GPIO5  → 按键1 (Lock 0)
│   ├── GPIO18 → 按键2 (Lock 1)
│   ├── GPIO25 → 按键3 (Lock 2)
│   └── GPIO26 → 按键4 (Lock 3)
│
└── 电源
    ├── VIN: 5V
    └── GND: 接地
```

### 7.2 硬件选型清单

| 序号 | 组件名称 | 型号 | 数量 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | ESP32主控板 | ESP32-WROOM-32 | 1 | 核心控制模块 |
| 2 | 指纹识别模块 | AS608 | 1 | UART接口 |
| 3 | 继电器模块 | 4路继电器 | 1 | 控制门锁 |
| 4 | 按键 | 轻触按键 | 4 | 手动触发 |

| 6 | 连接线 | 杜邦线 | 若干 | 连接各模块 |

### 7.3 门锁控制原理

- 继电器采用低电平触发或高电平触发（根据模块型号调整）
- 开锁时，GPIO输出有效电平，继电器吸合，门锁打开
- 延时3-5秒后，GPIO输出无效电平，继电器断开，门锁关闭
- 每个按键对应一个锁，按下按键触发指纹验证，验证通过后开锁

## 8. 安全考虑

### 8.1 数据安全

- 指纹模板在传输过程中进行加密
- 权限数据存储时进行校验和验证
- 通信数据采用校验和防止篡改

### 8.2 访问控制

- 系统管理员密码采用加密存储（SHA256）
- 上位机登录需要身份验证
- 权限变更需要管理员或老师授权

### 8.3 物理安全

- 指纹模块具有防拆卸保护
- 继电器输出增加保险丝保护
- 电源模块具有过流保护

### 8.4 网络安全

- 采用TCP协议，确保数据可靠传输
- 设置访问白名单，只允许指定IP连接
- 定期更改通信端口和密码
