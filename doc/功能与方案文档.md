# ESP32指纹锁实训柜权限管理系统 - 功能与方案文档

## 1. 项目概述

### 1.1 项目背景

本项目是针对学校实训场景设计的实训柜指纹权限管理系统。每个实训柜配备一个ESP32模块和指纹模块组成的指纹锁，通过WiFi与上位机进行通信，实现指纹权限的远程管理和分配。

### 1.2 项目目标

- 实现基于指纹识别的实训柜门锁控制
- 建立三级权限管理体系（系统管理员/老师/学生）
- 支持远程权限分配和管理
- 确保系统安全性和可靠性

### 1.3 应用场景

学校实训室中，每个实训柜配备一套指纹锁系统，学生和老师通过指纹识别打开对应的柜门，系统管理员负责整体权限管理。

## 4. 系统架构设计

### 4.0 ESP-MESH 自组网方案

#### 4.0.1 组网问题分析

当系统部署40个柜子（40台ESP32设备）时，传统WiFi路由器方案面临以下痛点：
- 需要部署企业级路由器/AP，且要求其能稳定承载40+客户端并发
- 每台ESP32都需要预先配置 WiFi SSID/密码、上位机IP/端口
- 路由器成为单点故障：路由器宕机整个系统瘫痪
- 实训柜金属外壳对WiFi信号衰减严重，单个AP覆盖可能不足
- 一旦换场地或换路由器，40台设备全部需要重新配网

#### 4.0.2 组网方案对比

| 方案 | 描述 | 优点 | 缺点 | 推荐度 |
| :--- | :--- | :--- | :--- | :--- |
| **方案A：路由器组网** | 部署路由器，所有ESP32作为客户端连接 | 实时通信、协议成熟 | 需路由器基础设施、配网繁琐、单点故障 | ★★★☆☆ |
| **方案B：ESP32开热点** | ESP32开AP热点，上位机逐个连接 | 无需路由器 | 不可扩展、无法实时管理40台 | ★☆☆☆☆ |
| **方案C：ESP-MESH自组网** | 40台ESP32自动组树状Mesh，根节点USB串口接上位机 | **零路由器、零配网、自动修复、单点接入** | 单跳延迟略增（可接受） | **★★★★★** |

#### 4.0.3 推荐方案：ESP-MESH 自组网 + USB串口桥接

**核心思想**：40台ESP32通过乐鑫官方 ESP-MESH 协议自动组成树状网络，其中**1台作为根节点（Root）**通过USB串口直连上位机。所有设备间通信走Mesh，根节点负责 Mesh ↔ 串口 双向转发。

#### 4.0.4 ESP-MESH 协议说明

**ESP-MESH** 是乐鑫官方为ESP32推出的WiFi Mesh协议（组件名 `esp_mesh`），特点：

| 特性 | 说明 |
| :--- | :--- |
| 拓扑结构 | 树状（也支持链状），自动维护父子关系 |
| 节点容量 | 官方标称支持数十至数百节点，40台设备完全在能力范围内 |
| 自组网 | 上电自动扫描、自动选举根节点、自动加入网络 |
| 自修复 | 任一节点掉线，子节点自动重新寻找父节点接入 |
| 通信方式 | 节点间通过Mesh层收发数据包，无需TCP连接 |
| 传输层 | 应用层 JSON 消息直接走Mesh数据包，无需TCP/UDP |
| 安全性 | 支持Mesh密码（AES加密），防止未授权节点加入 |
| 兼容硬件 | ESP32-WROOM-32 原生支持，无需额外模块 |

**树状拓扑示意（40节点典型结构）**：

```
                    [Root] ESP32#1 ◄─── USB串口 ───► 上位机
                   /      |      \
                  /       |       \
            [Node#2]  [Node#3]  [Node#4]
            /   \       |        /   \
       [Node#5][#6]  [Node#7][#8][#9]
          ...           ...        ...
        叶子层：约30+个节点
```

- 根节点：1台，固定为ESP32#1（可通过配置或自动选举）
- 中间节点：约6-10台，承担数据转发
- 叶子节点：约30台，只收发自己业务数据
- 推荐拓扑深度：3-4层（避免过深增加延迟）

#### 4.0.5 节点角色定义

| 节点角色 | 数量 | 硬件 | 职责 | 与上位机通讯 |
| :--- | :--- | :--- | :--- | :--- |
| **根节点 (Root)** | 1台 | ESP32 + USB线 | Mesh根 + 串口桥接 | USB串口直连 |
| **普通节点 (Node)** | 39台 | ESP32 | 指纹锁控制 + Mesh通讯 | 经Mesh路由到Root |

**根节点特殊处理**：
1. Mesh启动时设置为 `MESH_ROOT`（或开启自动选举，配置最高优先级）
2. 启用USB CDC虚拟串口（或UART0），与PC通讯
3. 在Mesh层与串口之间双向转发JSON消息包
4. 根节点本身也可以连接指纹锁（即可兼作1号实训柜）

**普通节点行为**：
1. Mesh启动时设置为 `MESH_NODE`，自动寻找父节点
2. 收到指纹/按键事件，通过 `esp_mesh_send()` 发往根节点
3. 监听Mesh层接收，处理上位机下发的命令
4. 与原TCP方案完全使用相同的消息格式（`Message` 结构不变）

#### 4.0.6 节点身份与设备编号映射

每个ESP32在Mesh网络中拥有两类身份：

| 身份类型 | 标识 | 用途 | 获取方式 |
| :--- | :--- | :--- | :--- |
| **Mesh Layer Address** | 6字节MAC | Mesh内部路由 | 启动时自动获取 |
| **Device ID** | 字符串（如 `CABINET_001`） | 业务层标识 | Flash预存 |

**上位机识别设备流程**：
1. ESP32上电组网成功后，向Root发送 `REGISTER` 消息（含 `device_id` 和 `device_name`）
2. Root转发到串口给上位机
3. 上位机记录 `device_id` ↔ Mesh MAC 映射
4. 后续命令通过 `device_id` 路由（Root内部维护 `device_id` → Mesh MAC 表）

#### 4.0.7 USB串口桥接设计

**串口参数**：

| 项目 | 值 | 说明 |
| :--- | :--- | :--- |
| 物理接口 | USB Type-C/Micro-USB | ESP32原生USB或CH340/CP2102 |
| 虚拟串口 | CDC (USB CDC) 或 UART0 | 优先用USB CDC，无需额外芯片 |
| 波特率 | `921600` bps | 高波特率降低传输延迟 |
| 数据位 | 8 / 无校验 / 停止位1 | 标准配置 |
| 流控 | 无 | 简化接线 |
| 消息分隔 | `\n` 换行符 | 与原TCP协议一致 |
| 数据格式 | JSON + `\n` | 与原TCP协议完全一致 |

**根节点串口桥接逻辑**：

```c
// mesh_bridge.cpp (根节点专用)
// Mesh层 → 串口：转发所有子节点上报的消息到PC
void onMeshReceive(const mesh_addr_t *from, const mesh_data_t *data) {
    // data->data 是 JSON 字符串
    Serial.write(data->data, data->size);
    Serial.write('\n');
}

// 串口 → Mesh层：把PC下发的命令按 device_id 路由到对应子节点
void onSerialReceive(const String &line) {
    Message msg = Message::parse(line);
    mesh_addr_t target = lookupDeviceId(msg.device_id);  // 查MAC表
    mesh_data_t data = { (uint8_t*)line.c_str(), line.length()+1, 0 };
    esp_mesh_send(&target, &data, MESH_DATA_P2P, NULL, 0);
}
```

#### 4.0.8 双模式保留（Mesh模式 + 调试模式）

为兼顾日常使用与单台调试，ESP32保留两种工作模式，通过按键切换：

| 模式 | 名称 | 触发条件 | 用途 | 通讯方式 |
| :--- | :--- | :--- | :--- | :--- |
| **Mesh模式** | 默认 | 上电默认 | 40台集中部署 | ESP-MESH + USB串口(Root) |
| **调试模式** | AP模式 | 长按按键10秒切换 | 单台调试/无Mesh环境 | ESP32开AP热点 + TCP |

**模式切换**：
- 长按4个按键中任意1个保持10秒
- ESP32重启并切换到另一种模式
- LED指示当前模式：Mesh模式慢闪 / 调试模式快闪

> 调试模式保留原 AP+TCP 方案，便于在没有Mesh网络的情况下对单台设备进行指纹录入、参数配置等操作。日常部署统一使用Mesh模式。

#### 4.0.9 上位机Mesh桥接设计

上位机将原 TCP 监听逻辑替换为 **USB串口桥接**，业务层完全不变：

```csharp
// Network/MeshBridge.cs  (替换原 TcpServer.cs)
// 通过USB串口与Mesh根节点通讯，管理40台ESP32
public class MeshBridge
{
    private SerialPort _port;
    private readonly Dictionary<string, DeviceClient> _devices = new();
    
    // 启动串口连接根节点
    public void Start(string portName = "COM3", int baudRate = 921600)
    {
        _port = new SerialPort(portName, baudRate);
        _port.DataReceived += OnSerialData;
        _port.Open();
        Console.WriteLine($"[Mesh] 已连接根节点 {portName}@{baudRate}");
    }
    
    // 串口收到数据 → 按行解析 → 走原有 MessageHandler
    private void OnSerialData(object s, SerialDataReceivedEventArgs e)
    {
        while (_port.ReadLine() is { } line)
        {
            var msg = Message.FromJson(line);     // 复用原 Message 模型
            if (msg?.Cmd == Protocol.CmdRegister)
                _devices[msg.DeviceId] = new DeviceClient(msg.DeviceId);
            
            MessageHandler.Handle(msg);           // 复用原消息处理
        }
    }
    
    // 上位机 → 设备：写入串口，根节点内部按 device_id 路由
    public void Send(string deviceId, string cmd, object data)
    {
        var msg = Message.Create(cmd, deviceId, data);
        _port.Write(msg.ToJson());                // JSON + \n
    }
}
```

> **关键点**：业务层（`Services/*`、`MessageHandler`、`Models/*`）零改动，仅 `Network/` 层实现替换。原 TCP 方案的消息格式、命令枚举、JSON 结构完全保留。

#### 4.0.10 离线缓存与断网容错

虽然Mesh根节点USB直连PC可靠性高，仍保留离线容错能力：

| 故障场景 | 系统行为 |
| :--- | :--- |
| 某子节点掉线 | Mesh自动重路由，该节点业务中断但其他节点正常 |
| 根节点USB断开 | 上位机立即检测到，所有设备离线缓存日志，根节点恢复后批量同步 |
| 单节点与Mesh失联 | 本地缓存开锁日志（最多100条），网络恢复后批量上报 |
| 上位机软件关闭 | ESP32继续工作（权限已缓存），日志本地保存，PC重启后同步 |

#### 4.0.11 部署使用流程

**首次部署**：
1. 烧录固件到40台ESP32（统一固件，通过Flash配置区分Root/Node）
2. 设置1台为Root节点（写入 `is_root=true` 配置）
3. Root节点通过USB连接PC
4. 上电后40台ESP32自动组网（约30-60秒）
5. 上位机打开串口，自动识别40台设备注册消息

**日常使用**：
1. 上位机启动 → 自动连接Root串口
2. 40台ESP32上电 → 自动加入Mesh网络
3. 用户按指纹 → 设备Mesh发往Root → Root串口转PC → PC验证后回传
4. 日志实时上传，权限变更实时下发

**新增/更换设备**：
1. 烧录相同固件，配置 `device_id`
2. 上电即可自动加入Mesh网络（无需任何配网操作）

**场地迁移**：
- 整体打包40台ESP32 + 1根USB线 + 1台PC
- 无需重新配网，上电自动组网

#### 4.0.12 硬件部署建议

**Root节点位置**：
- 放置在实训室中央位置，确保Mesh无线覆盖良好
- 通过USB延长线连接到上位机PC
- 单独供电（USB供电或独立5V电源）

**子节点布局**：
- 每台ESP32安装在实训柜内部，外接天线引出柜体（如信号衰减严重）
- 避免金属柜体完全封闭ESP32天线
- 相邻实训柜间距建议 < 10米（Mesh单跳可靠距离）

**Mesh网络优化**：
- 拓扑深度建议 ≤ 4 层
- 中间层节点选择信号好的位置（自动选举优先信号强度）
- 必要时增加1-2台纯转发节点（不接指纹锁，仅作Mesh中继）

## 5. 通信协议设计

### 5.1 通信方式

V2.0 方案采用 **ESP-MESH + USB串口** 双段通讯链路：

| 链路段 | 协议 | 介质 | 说明 |
| :--- | :--- | :--- | :--- |
| **设备 ↔ 根节点** | ESP-MESH (P2P) | WiFi 2.4G | 40台ESP32自组网，应用层JSON直接走Mesh数据包 |
| **根节点 ↔ 上位机** | USB CDC 虚拟串口 | USB | 921600 bps，JSON + `\n` 分隔 |

**关键特性**：
- 应用层消息格式与V1.0 TCP方案**完全一致**（JSON + `\n`）
- 业务层无需感知底层是TCP还是Mesh，仅Root做协议转换
- 调试模式（AP+TCP）保留作为单台设备维护通道

### 5.2 数据格式

采用JSON格式进行数据传输，每个数据包包含以下字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `cmd` | string | 命令类型 |
| `device_id` | string | 设备唯一标识（业务层路由依据） |
| `data` | object | 数据内容 |
| `timestamp` | string | 时间戳 |
| `checksum` | string | 校验和（可选） |

**消息封装链路**：

```
[业务层]    JSON 字符串 + \n
   │
   ▼
[ESP32子节点] esp_mesh_send(root, json_bytes)  ───►  [Root]  ───► Serial.write(json+\n)
                                                                  │
                                                                  ▼
[上位机业务层] JSON 字符串 + \n  ◄─── SerialPort.ReadLine()  ◄─── [PC串口]
```

### 5.3 命令列表

#### 5.3.1 下位机 → 上位机

> 以下命令通过 Mesh 上报到 Root，Root 透传到串口给上位机。"模式"列表示典型使用场景。

| 命令 | 说明 | 典型模式 | 数据结构 |
| :--- | :--- | :--- | :--- |
| `REGISTER` | 设备注册（含Mesh MAC） | Mesh | `{"device_name": "实训柜1", "mesh_mac": "A4:CF:12:..."}` |
| `FINGER_VERIFY` | 指纹验证请求 | 两者 | `{"fingerprint_id": 1}` |
| `STATUS_REPORT` | 状态上报 | Mesh | `{"online": true, "lock_status": [0, 0, 0, 0]}` |
| `LOG_REPORT` | 日志上报 | 两者 | `{"user_id": "U001", "lock_id": 1, "action": "open", "time": "2024-01-01 00:00:00"}` |
| `CONFIG_RESPONSE` | 配置读取响应 | 两者 | `{"device_id": "...", "wifi_ssid": "...", "server_ip": "...", ...}` |
| `STATUS_RESPONSE` | 状态读取响应 | 两者 | `{"uptime": 3600, "lock_status": [0,0,0,0], "log_count": 15}` |
| `CONFIG_SAVED` | 配置保存成功 | 两者 | `{"result": "success"}` |

#### 5.3.2 上位机 → 下位机

> 以下命令通过串口下发给 Root，Root 根据 `device_id` 查Mesh MAC表后 `esp_mesh_send` 到目标节点。

| 命令 | 说明 | 典型模式 | 数据结构 |
| :--- | :--- | :--- | :--- |
| `AUTH_OK` | 验证成功 | 两者 | `{"permissions": {"lock_0": true, "lock_1": true, "lock_2": true, "lock_3": true}}` |
| `AUTH_FAIL` | 验证失败 | 两者 | `{"reason": "用户不存在或权限不足"}` |
| `SYNC_PERMISSIONS` | 同步权限 | 两者 | `{"users": [...], "timestamp": "2024-01-01 00:00:00"}` |
| `ADD_FINGERPRINT` | 添加指纹 | 两者 | `{"user_id": "U001", "fingerprint_id": 1, "template": "..."}` |
| `DELETE_FINGERPRINT` | 删除指纹 | 两者 | `{"fingerprint_id": 1}` |
| `CONTROL_LOCK` | 控制锁 | 两者 | `{"lock_id": 1, "action": "open"}` |
| `READ_CONFIG` | 读取设备配置 | 两者 | `{}` |
| `WRITE_CONFIG` | 写入设备配置 | 两者 | `{"device_id": "CABINET_001", "wifi_ssid": "...", "server_ip": "...", ...}` |
| `READ_STATUS` | 读取设备状态 | 两者 | `{}` |
| `CLEAR_LOGS` | 清除本地日志 | 两者 | `{}` |
| `REBOOT` | 重启设备 | 两者 | `{"mode": "mesh"}` |

### 5.4 通信流程

#### 5.4.1 指纹验证流程（Mesh链路）

```
子节点            Root             上位机
  │                │                 │
  │── esp_mesh_send(FINGER_VERIFY) ──►│                 │
  │  (fingerprint_id)                │                 │
  │                                  │── Serial.write ─►│
  │                                  │  (JSON+\n)       │
  │                                  │                  ▼
  │                                  │             查询用户权限
  │                                  │                  │
  │                                  │◄── Serial.write ─│
  │                                  │  (AUTH_OK JSON)  │
  │◄── esp_mesh_recv(AUTH_OK) ───────│                  │
  │  (permissions)                                       │
  │                                                       │
  ▼                                                       │
 根据权限控制锁
```

#### 5.4.2 权限同步流程（Mesh链路）

```
上位机            Root             子节点
  │                │                 │
  │── Serial.write ─►│                 │
  │  (SYNC_PERM)     │                 │
  │                  │── esp_mesh_send ─►│

  │                  │                 │
  │                  │◄── esp_mesh_recv │
  │                  │  (SYNC_ACK)      │
  │◄── Serial.write ─│                  │

```

```
                              ▼

                              │
                              ▼

                              │
                              ▼
                  上位机记录 device_id ↔ Mesh MAC
                              │
                              ▼
```

**FreeSql 初始化示例**：

```csharp
// Models/User.cs
public class User
{
    [Column(IsPrimary = true, IsIdentity = false)]
    public string UserId { get; set; }
    
    public string Name { get; set; }
    
    public string Role { get; set; }  // admin/teacher/student
    
    public int? FingerprintId { get; set; }
    
    public DateTime CreateTime { get; set; }
    
    [Column(IsNullable = true)]
    public DateTime? UpdateTime { get; set; }
}

// Services/DatabaseService.cs
public class DatabaseService
{
    public static IFreeSql Fsql;

    public void InitDatabase()
    {
        Fsql = new FreeSql.FreeSqlBuilder()
            .UseConnectionString(FreeSql.DataType.Sqlite, 
                "Data Source=./Data/fingerprint_lock.db")
            .UseAutoSyncStructure(true)  // 自动创建表（Code First）
            .Build();
    }
}

// 使用示例
var user = new User 
{
    UserId = "U001", 
    Name = "张三", 
    Role = "student", 
    CreateTime = DateTime.Now 
};
fsql.Insert(user).ExecuteAffrows();  // 插入

var users = fsql.Select<User>().Where(u => u.Role == "student").ToList();  // 查询

fsql.Update<User>().SetSource(user).ExecuteAffrows();  // 更新

fsql.Delete<User>().Where(u => u.UserId == "U001").ExecuteAffrows();  // 删除
```

> **优点**：
> - 面向实体操作，代码简洁
> - Code First 自动建表，无需手动写SQL

```
├── GPIO输入 (按键)
│   ├── GPIO5  → 按键1 (Lock 0)
│   ├── GPIO18 → 按键2 (Lock 1)
│   ├── GPIO25 → 按键3 (Lock 2)
│   └── GPIO26 → 按键4 (Lock 3)
│
└── 电源
    ├── VIN: 5V
    └── GND: 接地
```

### 7.2 硬件选型清单

| 序号 | 组件名称 | 型号 | 数量 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | ESP32主控板 | ESP32-WROOM-32 | 1 | 核心控制模块 |
| 2 | 指纹识别模块 | AS608 | 1 | UART接口 |
| 3 | 继电器模块 | 4路继电器 | 1 | 控制门锁 |
| 4 | 按键 | 轻触按键 | 4 | 手动触发 |
| 5 | 电源模块 | 5V/2A | 1 | 供电 |
| 6 | 连接线 | 杜邦线 | 若干 | 连接各模块 |

### 7.3 门锁控制原理

- 继电器采用低电平触发或高电平触发（根据模块型号调整）
- 开锁时，GPIO输出有效电平，继电器吸合，门锁打开
- 延时3-5秒后，GPIO输出无效电平，继电器断开，门锁关闭
- 每个按键对应一个锁，按下按键触发指纹验证，验证通过后开锁

## 8. 安全考虑

### 8.1 数据安全

- 指纹模板在传输过程中进行加密
- 权限数据存储时进行校验和验证
- 通信数据采用校验和防止篡改

### 8.2 访问控制

- 系统管理员密码采用加密存储（SHA256）
- 上位机登录需要身份验证
- 权限变更需要管理员或老师授权

### 8.3 物理安全

- 指纹模块具有防拆卸保护
- 继电器输出增加保险丝保护
- 电源模块具有过流保护

### 8.4 Mesh 网络安全

- **Mesh密码保护**：ESP-MESH 启用 AES 加密，配置 Mesh 网络 password，未授权节点无法加入网络
- **白名单机制**：根节点维护允许加入的 MAC 白名单，拒绝陌生设备
- **USB直连隔离**：根节点 ↔ 上位机走USB物理串口，不暴露在无线网络中，无法被远程入侵
- **无外网暴露**：Mesh网络是封闭内网，不与互联网相连，避免远程攻击面
- **节点身份校验**：每个节点注册时上报 device_id + mesh_mac，上位机可双重校验
- **调试模式隔离**：AP+TCP 调试模式仅在维护时启用，日常关闭，避免开放无线热点

### 8.5 通讯链路可靠性

- Mesh层自动重传与重路由，单节点故障不影响整体通讯
- USB串口通讯稳定，无WiFi干扰风险
- 根节点心跳检测：上位机定期向Root发送HEARTBEAT，超时判定通讯中断
- 子节点离线缓存：Mesh断连时本地保存日志（最多100条），恢复后批量补传
