# ESP32指纹锁实训柜权限管理系统 - 功能与方案文档

## 1. 项目概述

### 1.1 项目背景

本项目是针对学校实训场景设计的实训柜指纹权限管理系统。每个实训柜配备一个ESP32模块和指纹模块组成的指纹锁，通过WiFi与上位机进行通信，实现指纹权限的远程管理和分配。

### 1.2 项目目标

- 实现基于指纹识别的实训柜门锁控制
- 建立三级权限管理体系（系统管理员/老师/学生）
- 支持远程权限分配和管理
- 确保系统安全性和可靠性

### 1.3 应用场景

学校实训室中，每个实训柜配备一套指纹锁系统，学生和老师通过指纹识别打开对应的柜门，系统管理员负责整体权限管理。

## 3. 权限管理方案

### 3.1 权限等级定义

| 权限等级 | 角色名称 | 权限描述 | 系统锁权限 |
| :--- | :--- | :--- | :--- |
| Level 1 | 系统管理员 | 可开启所有4个锁 | **有** |
| Level 2 | 老师 | 可开启除系统锁外的所有锁 | **无**（默认） |
| Level 3 | 学生 | 由老师分配指定锁的权限 | **无**（默认） |

### 3.2 锁编号规则

| 锁编号 | 锁名称 | 说明 |
| :--- | :--- | :--- |
| Lock 0 | 系统锁 | 仅系统管理员可开启 |
| Lock 1 | 实训柜1 | 老师和授权学生可开启 |
| Lock 2 | 实训柜2 | 老师和授权学生可开启 |
| Lock 3 | 实训柜3 | 老师和授权学生可开启 |

### 3.3 权限矩阵

| 角色 | Lock 0 (系统锁) | Lock 1 | Lock 2 | Lock 3 |
| :--- | :--- | :--- | :--- | :--- |
| 系统管理员 | ✅ | ✅ | ✅ | ✅ |
| 老师 | ❌ | ✅ | ✅ | ✅ |
| 学生（未授权） | ❌ | ❌ | ❌ | ❌ |
| 学生（授权Lock1） | ❌ | ✅ | ❌ | ❌ |

## 4. 系统架构设计

### 4.0 多设备组网方案

#### 4.0.1 组网问题分析

当系统部署40个柜子（40台ESP32设备）时，组网面临以下挑战：
- 如何让40台ESP32同时联网？
- 开锁日志如何实时上传？
- 权限同步如何下发？

#### 4.0.2 组网方案对比

| 方案 | 描述 | 优点 | 缺点 | 推荐度 |
| :--- | :--- | :--- | :--- | :--- |
| **方案A：路由器组网** | 部署1-2个WiFi路由器，所有ESP32作为客户端连接 | 实时通信、日志实时上传、稳定可靠 | 需部署路由器网络基础设施 | ★★★★★ |
| **方案B：ESP32开热点** | ESP32开AP热点，上位机逐个连接配置 | 无需路由器 | 配置繁琐、日志无法实时上传、不可行 | ★☆☆☆☆ |
| **方案C：离线缓存模式** | ESP32本地缓存权限和日志，定期同步 | 网络断开也能工作 | 日志延迟、权限同步不及时 | ★★★☆☆ |

#### 4.0.3 推荐方案：路由器组网 + 离线缓存

**推荐采用方案A为主，方案C为辅的混合架构**：

#### 4.0.4 路由器选型建议

| 场景 | 设备数量 | 推荐设备 | 说明 |
| :--- | :--- | :--- | :--- |
| 小型实训室 | ≤20台 | 普通家用路由器 | TP-Link/小米等，支持30+客户端 |
| 中型实训室 | 20-40台 | 企业级路由器或2个家用路由器 | 华硕/网件企业级，或双路由桥接 |
| 大型实训室 | >40台 | 企业级AP方案 | 多AP覆盖，同一局域网 |

**普通路由器连接能力**：
- 大多数家用路由器可稳定支持 **50-100个WiFi客户端**
- 40台ESP32 + 1台上位机 = 41个客户端，家用路由器完全可以承载
- 建议选择双频路由器（2.4G），ESP32只支持2.4G WiFi

#### 4.0.5 ESP32双通讯模式设计

ESP32支持两种平等的通讯模式，通过特殊按键操作切换。两种模式都是完整的通讯模式，不仅限于配置用途：

**模式切换触发方式**：
- 长按4个按键中的任意1个（或特定组合）保持10秒
- ESP32重启切换到另一种通讯模式，LED指示灯提示当前模式

| 模式 | 名称 | 触发条件 | ESP32角色 | 上位机角色 | 说明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **AP模式** | 热点模式 | 长按按键10秒切换 | TCP服务端 | TCP客户端 | ESP32开热点，上位机主动连接进去 |
| **STA模式** | 路由模式 | 默认启动 / 再次长按切换 | TCP客户端 | TCP服务端 | ESP32连接路由器，上位机监听等待连接 |

> 两种模式地位平等，都能进行全部功能操作（开锁、日志、权限同步、配置等），只是连接方向不同。

**模式1：AP模式（ESP32开热点，上位机连进来）**

```
┌─────────────────────────────────────────────────────┐
│                    AP模式通讯                        │
│                                                       │
│  长按按键10秒 → ESP32重启 → 开启AP热点               │
│                                                       │
│  ┌──────────────┐                ┌──────────────┐    │
│  │   ESP32      │   WiFi连接     │   上位机PC   │    │
│  │   AP热点     │◄──────────────►│  (连接热点)  │    │
│  │              │                │              │    │
│  │ SSID:        │   TCP连接      │  TCP客户端   │    │
│  │ ESP32_XXXX   │◄──────────────►│              │    │
│  │              │                │              │    │
│  │ TCP服务端    │  全功能通讯    │              │    │
│  │ 192.168.4.1  │◄──────────────►│              │    │
│  └──────────────┘                └──────────────┘    │
└─────────────────────────────────────────────────────┘

适用场景：
- 无路由器环境（临时使用、现场调试）
- 单台设备独立工作
- 故障排查、设备配置
```

**模式2：STA模式（ESP32连路由器，上位机监听）**

│  │              │                └──────┬───────┘    │

适用场景：
- 有路由器环境（实训室集中部署）
- 多台设备同时管理（40台ESP32）
- 日常使用

**AP模式热点信息**：
| 项目 | 值 | 说明 |
| :--- | :--- | :--- |
| SSID | `ESP32_<MAC后4位>` | 如 ESP32_A1B2，便于区分多台设备 |
| 密码 | `12345678` | 默认密码 |
| IP地址 | `192.168.4.1` | ESP32 AP模式默认网关 |
| TCP端口 | `8888` | AP模式下ESP32作为TCP服务端 |

**两种模式对比**：

| 对比项 | AP模式 | STA模式 |
| :--- | :--- | :--- |
| 网络依赖 | 无需路由器 | 需要路由器 |
| 连接方向 | 上位机主动连接ESP32 | ESP32主动连接上位机 |
| 设备数量 | 1对1（单台设备） | 1对多（40台设备） |
| ESP32角色 | TCP服务端 | TCP客户端 |
| 上位机角色 | TCP客户端 | TCP服务端 |
| 功能完整性 | 全功能 | 全功能 |
| 适用场景 | 临时/调试/无网络 | 日常集中管理 |

> **关键点**：无论哪种模式，开锁、日志上传、权限同步、设备配置等所有功能都完全可用，只是通讯链路的建立方式不同。

#### 4.0.6 上位机双模式适配

上位机需支持两种角色，通过界面切换：

| 通讯模式 | 上位机角色 | 连接方式 | 界面入口 |
| :--- | :--- | :--- | :--- |
| **STA模式**（多设备管理） | TCP服务端 | 监听 `0.0.0.0:8888`，等待ESP32连接 | 主界面（默认） |
| **AP模式**（单设备连接） | TCP客户端 | 主动连接 `192.168.4.1:8888` | "连接设备"按钮 |

**配置工具界面流程**：
1. 操作人员选择"连接设备"模式
2. PC连接ESP32的AP热点（SSID: ESP32_XXXX）
3. 上位机自动连接 `192.168.4.1:8888`
4. 进入完整的设备管理界面（与STA模式功能一致）
5. 可进行所有操作：开锁、查看日志、配置权限、修改设备参数

#### 4.0.7 上位机TCP服务端设计（STA模式用）

```csharp
// Network/TcpServer.cs
// STA模式：上位机作为TCP服务端，管理40+个ESP32连接
public class TcpServer
{
    private TcpListener _listener;
    private List<DeviceClient> _devices = new();  // 管理多个连接
    
    // 监听端口8888，等待ESP32连接
    public void Start(int port = 8888)
    {
        _listener = new TcpListener(IPAddress.Any, port);
        _listener.Start();
        
        // 异步接受连接（支持多设备并发）
        while (true)
        {
            var client = _listener.AcceptTcpClient();
            var device = new DeviceClient(client);
            _devices.Add(device);
            // 每个设备独立线程处理消息
            Task.Run(() => HandleDevice(device));
        }
    }
}
```

#### 4.0.8 上位机TCP客户端设计（AP模式用）

```csharp
// Network/DeviceClient.cs
// AP模式：上位机作为TCP客户端，连接ESP32热点
public class DeviceClient
{
    // AP模式下，上位机主动连接ESP32
    public async Task ConnectAsync(string ip = "192.168.4.1", int port = 8888)
    {
        var client = new TcpClient();
        await client.ConnectAsync(ip, port);
        
        // 连接成功后，进入完整的设备管理界面
        // 所有功能与STA模式一致：开锁、日志、权限、配置
        StartReceiving(client);
    }
}
```

> 两种模式上位机使用相同的消息处理逻辑（MessageHandler），只是连接建立方式不同。

#### 4.0.9 部署使用建议

**STA模式网络配置**（有路由器环境）：
```

ESP32设备IP：192.168.1.101 ~ 192.168.1.140（DHCP分配或静态IP）

- SSID: TrainingRoom_WiFi
- Password: 12345678

**AP模式使用**（无路由器环境 / 单台操作）：
```

热点密码：12345678
ESP32地址：192.168.4.1
TCP端口：8888

操作步骤：
1. ESP32上电，长按按键10秒切换到AP模式

1. 安装路由器，配置WiFi名称和密码
2. 上位机连接路由器，设置固定IP `192.168.1.100`
3. 启动上位机TCP服务端
4. ESP32上电自动连接路由器并连接上位机
5. 40台ESP32全部联网后，上位机显示40个在线设备

## 5. 通信协议设计

### 5.1 通信方式

- **协议**: TCP/IP
- **端口**: 8888（可配置）
- **连接方式**: 下位机主动连接上位机

### 5.2 数据格式

采用JSON格式进行数据传输，每个数据包包含以下字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `cmd` | string | 命令类型 |
| `device_id` | string | 设备唯一标识 |
| `data` | object | 数据内容 |
| `timestamp` | string | 时间戳 |
| `checksum` | string | 校验和 |

### 5.3 命令列表

#### 5.3.1 下位机 → 上位机

> 以下命令在AP和STA两种模式下均可用，"模式"列仅表示典型使用场景。

| 命令 | 说明 | 典型模式 | 数据结构 |
| :--- | :--- | :--- | :--- |
| `REGISTER` | 设备注册 | STA | `{"device_name": "实训柜1"}` |
| `FINGER_VERIFY` | 指纹验证请求 | 两者 | `{"fingerprint_id": 1}` |
| `STATUS_REPORT` | 状态上报 | STA | `{"online": true, "lock_status": [0, 0, 0, 0]}` |
| `LOG_REPORT` | 日志上报 | 两者 | `{"user_id": "U001", "lock_id": 1, "action": "open", "time": "2024-01-01 00:00:00"}` |

| `CONFIG_SAVED` | 配置保存成功 | 两者 | `{"result": "success"}` |

#### 5.3.2 上位机 → 下位机

> 以下命令在AP和STA两种模式下均可用，"模式"列仅表示典型使用场景。

### 6.0 数据库技术方案

| 项目 | 技术选型 | 说明 |
| :--- | :--- | :--- |

**FreeSql 初始化示例**：

```csharp
// Models/User.cs
public class User
{
    [Column(IsPrimary = true, IsIdentity = false)]
    public string UserId { get; set; }
    
    public string Name { get; set; }
    
    public string Role { get; set; }  // admin/teacher/student
    
    public int? FingerprintId { get; set; }
    
    public DateTime CreateTime { get; set; }
    
    [Column(IsNullable = true)]
    public DateTime? UpdateTime { get; set; }
}

// Services/DatabaseService.cs
public class DatabaseService
{
    public static IFreeSql Fsql;

    public void InitDatabase()
    {
        Fsql = new FreeSql.FreeSqlBuilder()
            .UseConnectionString(FreeSql.DataType.Sqlite, 
                "Data Source=./Data/fingerprint_lock.db")
            .UseAutoSyncStructure(true)  // 自动创建表（Code First）
            .Build();
    }
}

// 使用示例
var user = new User 
{
    UserId = "U001", 
    Name = "张三", 
    Role = "student", 
    CreateTime = DateTime.Now 
};
fsql.Insert(user).ExecuteAffrows();  // 插入

var users = fsql.Select<User>().Where(u => u.Role == "student").ToList();  // 查询

fsql.Update<User>().SetSource(user).ExecuteAffrows();  // 更新

fsql.Delete<User>().Where(u => u.UserId == "U001").ExecuteAffrows();  // 删除
```

> **优点**：
> - 面向实体操作，代码简洁
> - Code First 自动建表，无需手动写SQL
> - 单文件发布完全支持，FreeSql.Provider.Sqlite 会被打包进去

## 7. 硬件设计

### 7.1 硬件连接图

```
ESP32-WROOM-32
├── UART2 (TX: GPIO17, RX: GPIO16)
│   └── AS608指纹模块
│       ├── VCC: 3.3V
│       ├── GND: GND
│       ├── TX: GPIO16 (ESP32 RX)
│       └── RX: GPIO17 (ESP32 TX)
│
├── GPIO输出 (继电器控制)
│   ├── GPIO23 → 继电器1 (Lock 0)
│   ├── GPIO22 → 继电器2 (Lock 1)
│   ├── GPIO21 → 继电器3 (Lock 2)
│   └── GPIO19 → 继电器4 (Lock 3)
│
├── GPIO输入 (按键)
│   ├── GPIO5  → 按键1 (Lock 0)
│   ├── GPIO18 → 按键2 (Lock 1)
│   ├── GPIO25 → 按键3 (Lock 2)
│   └── GPIO26 → 按键4 (Lock 3)
│
└── 电源
    ├── VIN: 5V
    └── GND: 接地
```

### 7.2 硬件选型清单

| 序号 | 组件名称 | 型号 | 数量 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | ESP32主控板 | ESP32-WROOM-32 | 1 | 核心控制模块 |
| 2 | 指纹识别模块 | AS608 | 1 | UART接口 |
| 3 | 继电器模块 | 4路继电器 | 1 | 控制门锁 |
| 4 | 按键 | 轻触按键 | 4 | 手动触发 |
| 5 | 电源模块 | 5V/2A | 1 | 供电 |
| 6 | 连接线 | 杜邦线 | 若干 | 连接各模块 |

### 7.3 门锁控制原理

- 继电器采用低电平触发或高电平触发（根据模块型号调整）
- 开锁时，GPIO输出有效电平，继电器吸合，门锁打开
- 延时3-5秒后，GPIO输出无效电平，继电器断开，门锁关闭
- 每个按键对应一个锁，按下按键触发指纹验证，验证通过后开锁

## 8. 安全考虑

### 8.1 数据安全

- 指纹模板在传输过程中进行加密
- 权限数据存储时进行校验和验证
- 通信数据采用校验和防止篡改

### 8.2 访问控制

- 系统管理员密码采用加密存储（SHA256）
- 上位机登录需要身份验证
- 权限变更需要管理员或老师授权

### 8.3 物理安全

- 指纹模块具有防拆卸保护
- 继电器输出增加保险丝保护
- 电源模块具有过流保护

### 8.4 网络安全

- 采用TCP协议，确保数据可靠传输
- 设置访问白名单，只允许指定IP连接
- 定期更改通信端口和密码
