# 设备与权限同步设计

更新时间：2026-08-04

本文描述当前实现的设备生命周期、权限分配和离线同步规则。

## 1. 设备生命周期

- 柜机首次通过 `REGISTER`/心跳被上位机看到后，立即合并进 `devices` 本地业务表。
- 设备记录与在线状态分离：记录长期保留，`IsOnline` 仅由最近心跳和路由超时决定。
- 上位机重启、柜机离线或根节点暂时不可用时，历史柜机仍显示并允许编辑名称、编号和学生分配。
- 删除柜机是显式业务操作，会同时解除学生绑定、清除该柜任务并从 Mesh 已知设备表移除。
- `devices` 随业务库上传到根节点 SD；根节点不在心跳路径频繁改写 SD，避免 50 台设备造成写放大。

## 2. 权限规则

| 角色 | 目标柜机 | 锁权限 |
| --- | --- | --- |
| 管理员 | 所有已记录柜机 | 4 把锁 |
| 教师 | 所有已记录柜机 | 角色默认值及个人覆盖，锁 0 强制禁止 |
| 学生 | `cabinet_assignments` 指定柜机 | 绑定记录的锁集合及个人覆盖，锁 0 强制禁止 |

柜机以本地权限缓存鉴权，开锁不依赖上位机或根节点在线。

## 3. 即时与离线同步

业务写入先提交 `business.db`，再写入持久化 `cabinet_sync_queue`：

- 新增/修改用户权限：`SYNC_PERMISSION` 单用户增量核对并写入。
- 删除用户、停用用户、解除学生分配：`DELETE_USER_PERMISSION` 按用户幂等删除。
- 指纹选择变化、柜级手动校准、未知旧记录清理：事务式
  `BEGIN_PERMISSION_SYNC -> SYNC_PERMISSION[n] -> COMMIT_PERMISSION_SYNC`。
- 柜机在线时立即触发；离线时任务保留，收到连接或注册事件后自动重试。
- 同一用户与同一柜机的反复新增/修改/删除会压缩成最终意图。
- 执行中的任务使用更新时间租约；执行期间出现的新修改不会被旧任务完成结果覆盖。
- 失败采用 5 秒起步、最高 5 分钟的指数退避。

班级启用、停用和删除同样不再要求全部柜机在线：业务状态立即生效，在线柜立即处理，离线或失败柜进入队列。

## 4. 版本与数据权威

权限版本统一由以下四个计数按 FNV-1a 顺序合成：

1. `users_version`
2. `classes_version`
3. `permissions_version`（包含 `role_permissions`）
4. `fp_version`

上位机在线时，当前 `business.db` 可能比 SD 更新，因此上位机队列是唯一在线下发者；根节点不得用旧 SD 快照覆盖柜机。上位机离线时，根节点才依据 SD 快照为重新注册的柜机补同步。

根节点离线补同步使用柜机三阶段事务，柜机只有在收齐全部记录后才原子提交，因此中途丢行或断电不会产生半套权限。当前 Root 端按柜串行、按行节流并依赖 Mesh 传输重试，但发送 `COMMIT` 后不等待应用层 `SYNC_ACK`；最终失败由柜机事务超时保留旧权限，并在下次 `REGISTER` 时再次比较版本、重新收敛。真机验收必须验证这一重注册路径。

## 5. 并发与网络控制

- 上位机后台队列由单个处理器消费，每轮最多 20 项；同一柜机的命令由 `CommandService` 串行门控。
- 命令使用固定 `msg_id` 重试，柜机缓存响应，重复包不重复执行业务。
- 柜级事务行间隔 40ms，柜间隔 100ms；根节点离线补同步也一次只处理一台柜机。
- 人工批量核对最多 3 台并发探测，不会让 50 台柜同时向串口回包。
- 柜机只有收到 ACK/结果后任务才完成；超时或链路错误保留任务并退避重试。

## 6. 验收重点

自动化测试和编译只能证明软件契约。部署前仍需完成 2/10/40/50 台真机测试：随机上电顺序、Root 重启、USB 断连、5%~20% 丢包、同步中断电、SD 拔插，以及队列在设备恢复在线后的最终收敛。

每组测试至少记录：柜机数量、上电顺序、丢包率、业务版本、各柜最终版本、待同步任务数、收发/重试计数和最大收敛时间。通过标准是业务配置始终可保存、柜机不出现半套权限、恢复链路后队列最终清空、所有目标柜版本一致，且串口没有持续回包风暴。
