# 业务数据存放形态说明

> 组网与硬件基线见 `系统架构与组网说明.md`（N16R8、Mesh 多柜、单柜 UART）。

## 直接回答

### 1. 为什么还会看到「协议 JSON」？

通讯日志里的 **「协议 JSON / 协议 JSON(兼容)」** 表示：外层 A5 帧里的**整包消息体**是 `{"cmd":...}` 文本，而不是 `B1 0F` 二进制信封。

这和下面两件事要分开：

| 日志/现象 | 含义 | 是否正常 |
|---|---|---|
| `协议 BIN` + payload 里是 JSON 文本 | 二进制信封，复杂 data 用 JSON | **正常（主路径）** |
| `协议 JSON` / `协议异常(整包JSON)` | 整包仍是旧 JSON 消息 | **异常 / 旧固件** |

本轮已把根节点上行 `sendToUplink`、柜子 UART0 `uartHostSendRaw`、以及 `sendMessage` 的 JSON 兜底收紧为：**能转二进制就转，转不了就丢弃并打日志**。刷入新固件后，上位机正常不应再刷「整包 JSON」日志。

### 2. 业务库是不是应该把整个 `business.db` 传到 SD？

**当前设计：不是传 SQLite 文件。**

| 位置 | 实际文件 | 谁读写 |
|---|---|---|
| 上位机本机 | `business.db`（SQLite） | 上位机运行期读写 |
| 根节点 SD 卡 | `/sdcard/data/*.json` 分表文件 | 根节点 FatFS 读写 |
| 同步方式 | `SD_QUERY` / `SD_SAVE` 按表传 JSON 数组 | 协议消息，不是文件拷贝 |

SD 上实际是：

```text
/sdcard/data/
  version.json
  users.json
  classes.json
  permissions.json
  role_permissions.json
  devices.json
  logs.json
  fingerprints/
    index.json
    FP_xxxxx.bin
```

上位机启动：`SD_QUERY` 逐表拉 JSON → 写入本机 `business.db`
上位机关闭/手动同步：`business.db` 逐表导出 JSON → `SD_SAVE` 写回 SD

学生与柜机的分配关系属于用户业务数据，保存在 `users.json` 的
`assigned_device_ids` 数组中，因此与用户表一起完成上述双向同步；柜机通讯仍使用
`device_id`，现场展示和选择优先使用可编辑且唯一的 `device_number`。

### 3. 根节点有没有能力读写 SQLite？

**基本没有，也不该依赖它。**

- ESP32 根节点用的是 **SD_MMC + FatFS**，业务实现是 **读/写 JSON 文本文件**（`SdStorage::readTable/writeTable`）。
- 虽然技术上可以移植 sqlite3 到 ESP32，但 Flash/RAM、断电一致性、并发与版本控制成本都很高，且与现有 JSON 表/乐观锁协议不兼容。

所以权威源是 **SD 上的 JSON 表**，上位机 SQLite 只是**本地工作副本/缓存**，方便 UI 查询和离线登录。

### 4. 要不要改成「整库 .db 文件互传」？

可以做，但**不推荐作为当前架构**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 现状：JSON 分表 + 本机 SQLite | 根节点实现简单；可单表同步；版本号清晰 | 同步是逻辑复制，不是文件镜像 |
| 整库 `business.db` 上传下载 | 概念简单 | ESP32 难直接用 SQLite；大文件分片/校验/并发冲突；柜子权限下发仍要再导出 |

若目标是「多上位机共享权威数据」，**JSON 分表在根节点 SD** 更合适。
若目标是「上位机只当纯 UI，永不落库」，那应改成运行期每次都 `SD_QUERY`（会更慢），而不是传 `.db` 文件。

### 5. 建议的心智模型

```text
权威数据：根节点 SD（JSON 表）
    ↕  启动拉 / 退出推 / 手动同步
上位机工作副本：business.db（SQLite）
    ↕  权限变更后
柜子本地缓存：NVS/权限表（二进制缓存，不是 SQLite）
```

**协议层**：A5 帧 + B1 信封（二进制）
**业务载荷**：复杂对象仍用 JSON（在信封 payload 内）
**存储层**：SD=JSON 文件，PC=SQLite，两者通过表级同步对齐
