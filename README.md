# edu-training-cabinet-fingerlock

学校实训柜指纹智能锁系统。

## 目录结构

- `FingerprintLockManager/`：Windows 上位机（WPF）
- `esp32_firmware/root_node/`：ESP32 根节点固件，负责 Mesh 汇聚、上行通信、SD 卡和显示屏
- `esp32_firmware/cabinet_node/`：ESP32 柜子节点固件，负责指纹识别、按键和锁控制
- `esp32_firmware/common/`：两个固件工程共用的协议、Mesh 通信和调试代码
- `doc/`：系统功能与方案文档
- `esp32_firmware/doc/`：ESP32、根节点及硬件资料
- `esp32_firmware/doc/柜子/IO分配.md`：柜子节点真实 GPIO / 74HC595 / UART0 调试口接线表

ESP 固件统一使用 PlatformIO，两个节点是相互独立的工程：

```text
cd esp32_firmware/root_node
pio run

cd ../cabinet_node
pio run
```

根目录不再放置 `root_node`、`cabinet_node` 或 `common` 的副本。

## 系统职责

- 柜子节点：指纹录入、指纹匹配、权限判断和开锁全部在本地完成。柜子保存权限缓存和离线日志，断网不影响已同步权限的验证；联网只用于管理命令、配置同步和日志上报。
- 根节点：维护 ESP-MESH，所有柜子到上位机的消息都经过根节点；根节点也是唯一业务数据中心，用户、角色权限、设备状态、日志和指纹模板保存在 SD 卡。
- 上位机：启动时从根节点 SD 拉取业务表到本机 `business.db`，运行期使用本机库；关闭或手动同步时再回写 SD。上位机离线不参与柜机鉴权，也不影响柜机与根节点之间的运行。
- **单柜调试**：柜子 `MODE_DEBUG` 下用 **UART0（GPIO43/44，921600）** 与上位机直连，协议帧与根节点 USB 上行相同，便于不经 Mesh 单独控制。

数据流约束：`柜子本地验证 -> 根节点保存日志 -> 上位机查询/展示`；管理变更运行期从上位机本地业务库按柜单播到柜机，关闭或手动同步时再将业务库回写根节点 SD。

班级管理可按单台、多选或全部在线柜机分配整班学生，并检测、差异同步指纹和权限；老师主指纹默认面向全部柜机，可在老师管理页按同样方式检测和同步。学生与柜机的分配关系保存在 `users.json` 的 `assigned_device_ids` 中，随既有 SD 同步流程往返。

## V2.7 柜机本地交互（窗口化验证 + 副指纹）

- **10 秒操作窗口**：用户按压指纹头验证成功后，进入 10 秒操作窗口期；窗口期内按下对应锁按键即开锁，超时未操作或按取消键则清空本次验证权限。识别中绿灯慢闪，成功绿灯常亮，失败红灯闪烁 3 次。
- **设备专属副指纹**：单台柜子可本地录入"副指纹"以解决部分设备识别不灵敏的问题；副指纹仅在本机生效，不上报 SD 卡、不影响全局主指纹。全局主指纹从低槽位向上分配，本机副指纹从高槽位向下分配，降低两个独立分配器的槽位碰撞概率。
- **三层角色数据隔离**：管理员可见全部数据；教师仅可见本班学生（Service 层 `IDataScopeContext` 强制过滤，非仅 UI 隐藏）；学生仅可见自己的日志。

## 上位机兜底登录

根节点数据服务或 SD 卡不可用时，上位机可使用内置超级管理员 `admin / admin123` 登录。根节点数据正常时不会启用该兜底密码，登录仍以 SD 卡中的账号数据为准。

## 协议说明

线上统一为 **外层 A5/5A 帧 + 应用层 B1/0F 二进制信封**；复杂业务 data 仍在信封 payload 内用 JSON。详见 `doc/协议统一说明.md`。

业务数据形态（SD JSON 表 vs 本机 SQLite）见 `doc/业务数据存放形态说明.md`。
